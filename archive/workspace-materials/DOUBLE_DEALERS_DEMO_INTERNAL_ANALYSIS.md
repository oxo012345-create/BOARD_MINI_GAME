## 1. 결론

설치된 데모에는 Unity IL2CPP 실행 파일뿐 아니라 개발용 백업 폴더, `Assembly-CSharp.dll`, IL2CPP가 생성한 C++ 코드와 PDB가 함께 들어 있다. 따라서 영상에서 짐작한 값이 아니라 실행 코드와 직렬화된 씬/프리팹 값을 서로 대조할 수 있었다.

- 아이템 29종, 조항 25종(ID 0~24), 카드 22종(ID 0~21)
- 아이템 인벤토리 4칸, 카드 인벤토리 3칸
- 시작 자금 `$2,000`
- 경매 50초, 종료 후 처리 10초, 판매 아이템 선택 20초, 상점 60초
- 경매 시작가 `$100`, 입찰 증가 단위 `$50`
- 종료 3초 이내 유효 입찰이 들어오면 5초 추가
- 씬 기본 라운드 수 5. 로비 설정값으로 덮어쓸 수 있음
- 카드 상점은 플레이어별 3장 제시
- 리롤은 `$100 → $200 → $300 → …`, 성공할 때마다 `$100` 상승
- 시대 보너스는 같은 시대 2개 `×1.5`, 3개 `×2.0`, 4개 이상 `×2.5`

기존 영상 기반 콘티의 “6라운드 고정”, “리롤은 매회 $100”, “경매 60초”는 이 설치 빌드와 일치하지 않는다.

## 2. 실제 게임 흐름

1. 서버가 각 플레이어에게 `$2,000`을 지급한다.
2. 라운드 시작 시 각 플레이어가 판매 후보 3개 중 1개를 고른다. 제한 시간은 20초다.
3. 판매자 순서를 섞고, 각 판매자의 경매를 50초간 진행한다.
4. 입찰은 `$100`에서 시작해 `$50` 단위로 오른다.
5. 남은 시간이 3초 이하일 때 유효 입찰이 들어오면 5초가 추가된다.
6. 종료 후 약 10초 동안 낙찰·가격·조항과 후속 효과를 처리한다.
7. 전원이 한 번씩 판매한 뒤 시장/카드 상점이 60초간 열린다.
8. 라운드 종료 효과를 계산하고 설정된 라운드 수만큼 반복한다.
9. 마지막에 현금 순위를 계산한다.

`gameLength`의 씬 기본값은 5이며 시작 화면이 PlayerPrefs로 넘긴 로비 설정값이 있으면 교체한다. 즉 데모 내부 구조는 “6라운드 고정”이 아니다.

## 3. 아이템 생성 규칙

모든 확인된 아이템 프리팹의 기준 가격은 `$500`이다.

- 정수 난수 `-500~+500`을 기준 가격에 더한다.
- 0 미만은 0으로 제한하고 `$10` 단위로 반올림한다.
- 일반적인 생성 범위는 `$0~$1,000`이다.
- 조항 15가 붙으면 일반 가격 대신 `-$250`에서 시작한다.
- 판매자에게 보이는 추정 하한은 실제 가격의 무작위 `50~85%`이며 실제가보다 최소 `$10` 낮게 보정한다.
- 추정 상한은 실제 가격의 무작위 `110~160%`이며 실제가보다 최소 `$10` 높게 보정한다.
- 추정 범위도 `$10` 단위로 반올림한다.
- 활성 조항 중 서로 다른 2개를 무작위로 붙인다.

판매자는 실제 가격과 두 조항을 알고, 다른 플레이어는 시대만 공개적으로 확인하는 구조다.

### 데이터 불일치

현지화 문구, 오래된 프리팹 설명, 실제 실행 코드가 어긋난 곳은 실행 코드를 기준으로 정리했다.

- Hammer Lock: 현지화는 1회, 일부 프리팹은 2회라고 쓰였지만 실행 코드는 다음 hand에서 해제하므로 1회가 맞다.
- Loan Shark: 문구는 “2 hands 뒤”, 내부 지연 상수는 3이다. 현재 hand를 포함한 절대 인덱스로 계산하므로 사이에 2개 hand가 지난 뒤 상환한다.
- All In II: 현지화가 확률/배율을 뒤섞었지만 실행 필드는 성공 확률 50%, 성공 보너스 35%다.
- Robin Hood: 현지화와 코드는 `$250` 강탈, 프리팹에는 오래된 `$500` 설명이 남아 있다. 이 설치 프리팹 가격은 `$150`이다.

## 7. 카드 상점과 리롤

- 각 플레이어에게 개별 카드 3장을 제시한다.
- 같은 묶음 안에서는 중복되지 않는다.
- 직전 제시 3종을 우선 제외한다. 후보가 3개 미만이면 제외를 풀어 채운다.
- 이미 보유했거나 영구 효과가 활성화되어 중복될 수 없는 카드 ID는 후보에서 막는다.
- 상점 시작 시 리롤은 `$100`, 성공할 때마다 기준 비용 `+$100`이다.
- Reroll Saver I은 실제 차감액을 `round(기준 비용 × 0.9)`로 만든다.
- Reroll Saver II는 `round(기준 비용 × 0.8)`이며 둘 다 켜져 있으면 II만 적용된다.
- 조항 3은 할인 후 지불액이 아니라 성공한 리롤 횟수를 센다.

### 희귀도 구현 버그

코드는 `weight = max(0.0001, 0.5 ^ int(cardRarity))`로 계산한다. 현재 프리팹의 희귀도 값은 모두 `0.1~0.7`이므로 전부 `int(rarity)=0`, 결과적으로 모든 사용 가능한 카드의 가중치가 1이다. 현 빌드에서는 희귀도 표기가 사실상 작동하지 않고 후보 카드가 균등 추첨된다.

## 8. 인벤토리와 시장

- 아이템 인벤토리는 4칸, 카드 인벤토리는 3칸이다.
- 같은 시대 아이템의 최대 묶음 수에 따라 체크아웃 전체 기준 가격에 보너스를 붙인다.
  - 2개: `×1.5`
  - 3개: `×2.0`
  - 4개 이상: `×2.5`
- 조항 8은 시대 카운트에서 와일드카드처럼 작동한다.
- 이후 개별 조항, 카드 수, 빈 슬롯, 리롤 횟수 등의 조건부 보정이 적용된다.

## 9. 휴대폰 오프라인 대화형 버전에 반영할 값

- 실제 말하기·거짓말·협상은 사람끼리 구두로 진행한다.
- 각 휴대폰에는 본인 비밀 정보, 돈, 카드, 아이템, 상점, 입찰만 표시한다.
- 서버는 50초 경매, 3초/5초 연장, `$100` 시작가, `$50` 단위를 강제한다.
- 판매 후보 3개, 아이템 4칸, 카드 3칸을 유지한다.
- 60초 상점과 누적 리롤 비용을 유지한다.
- 29개 아이템의 이름·시대·가격 구조와 25개 조항·22개 카드의 실행 효과를 데이터 테이블로 구현한다.
- 원본 3D 모델·텍스처·로고·음원은 복사하지 말고 새로 제작한다.

## 10. 분석 범위와 파일
