## 0. 이 문서의 원칙

이 문서는 공개된 `Double Dealers - Demo`의 실제 플레이 영상, Steam 소개, 공식 업데이트에서 확인한 규칙만을 원작 기준으로 사용한다. 앞서 작성했던 창작 조항 55개는 이 버전의 기본 게임에 넣지 않는다.

표기는 다음처럼 통일한다.

- **[확인]** 공식 설명, 공식 업데이트, 실제 게임 화면에서 직접 확인
- **[현장 변환]** 원작 기능을 휴대폰·대면 플레이에 맞게 입력 방식만 바꾼 것
- **[가안]** 공개 자료만으로 정확한 값이 보이지 않아 서버 설정값으로 둔 것
- **[검증 잠금]** 이름이나 화면은 보였지만 정확한 효과·수식은 판독되지 않아 출시 데이터에서 비활성화할 것

### 반드시 지킬 범위

원작과 같거나 매우 비슷하게 유지할 요소:

- 3~6인
- 각 플레이어 시작 아이템 후보 3개
- 한 명씩 판매자가 되어 아이템 1개 경매
- 판매자만 실제 시장가와 2개 조항을 확인
- 구매자는 가치와 조항을 모른 채 실제 대화로 추리
- 실시간 입찰, 최고 입찰자 낙찰
- 낙찰 뒤 실제 가치·조항 공개
- 모든 사람이 한 번씩 판매한 뒤 시장/상점 단계
- 아이템 보유 또는 판매
- 같은 시대 아이템 묶음 판매 보너스
- 카드 3장 상점, 카드 구매, `$100`부터 매회 `$100`씩 비싸지는 리롤
- READY/UNREADY와 제한 시간
- 로비에서 정한 라운드가 끝난 뒤 현금이 가장 많은 사람이 승리
- 조항으로 발생하는 카드 제한, 침묵, 가격 변화, 보유 위험, 권투

달라지는 요소는 하나다.

- 원작의 온라인 음성 채팅을 없애고, 같은 자리에 있는 사람들이 실제로 말한다.

입력 장치가 PC에서 휴대폰으로 바뀌므로 키보드 조작은 터치 버튼과 제스처로 바꾸되, 게임 결과와 정보 비대칭은 그대로 유지한다.

### 저작권·상표 적용 원칙

기능과 게임 구조를 참고하더라도 출시 제품은 원작 로고, 게임명, 캐릭터, 3D 모델, 텍스처, 폰트, 음악, 효과음을 복제하지 않는다. 아이템 종류와 규칙 데이터는 검토하되 시각 자산은 새로 제작한다. “기능적 충실도”와 “자산 복제”를 분리한다.

## 1. 한 문장 정의

판매자만 진짜 가치와 함정을 아는 물건을 테이블 위 친구들에게 말로 포장해 비싸게 넘기고, 구매자는 거짓말을 간파해 되팔아 돈을 버는 3~6인 휴대폰 경매 파티게임이다.

## 2. 권장 기술 구성

### 2.1 클라이언트

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | React + TypeScript + Vite | 경매, 상점, 인벤토리처럼 UI 상태가 많은 모바일 웹에 적합 |
| 3D 엔진 | Babylon.js | glTF/GLB, PBR 재질, 조명, 카메라, 모바일 WebGL 최적화를 한 엔진에서 처리 |
| 상태 관리 | Zustand | 서버 상태와 화면 상태를 단순하게 분리 |
| 실시간 통신 | WebSocket | 입찰·타이머·READY·권투 입력을 즉시 동기화 |
| 진동 | Vibration API + 무지원 기기 폴백 | 낙찰, 입찰 추월, 조항 발동 피드백 |
| 설치형 경험 | PWA | 홈 화면 추가, 전체 화면, 재접속 편의 |

3D는 게임 전체를 3D로 만들지 않는다. `경매 물건 + 받침대 + 조명 + 짧은 연출`만 3D로 두고, 입찰·상점·조항은 HTML UI로 만든다. 이 구성이 저사양 휴대폰에서도 가장 안정적이다.

### 2.2 서버

권장안은 `Cloudflare Workers + Durable Objects + WebSocket`이다.

- 방 하나를 Durable Object 하나가 전담한다.
- 돈, 입찰, 타이머, 아이템, 조항, 카드 사용 결과는 모두 서버가 판정한다.
- 클라이언트 시간 대신 서버의 `endsAt`을 기준으로 한다.
- 마지막 100개 이벤트를 방 로그에 보관해 재접속 시 복원한다.
- 정적 웹과 3D 자산은 Cloudflare Pages/R2/CDN에서 제공한다.
- D1에는 계정이 아니라 익명 통계, 게임 결과, 오류 기록만 선택 저장한다.

초기 버전은 회원가입 없이 방 코드와 닉네임만 사용한다. 술자리 게임에서 로그인은 이탈 요인이므로 넣지 않는다.

### 2.3 서버가 반드시 권위를 가져야 하는 값

- 플레이어별 현금
- 아이템 소유권
- 실제 시장가
- 조항 2개
- 카드 보유·사용·폐기
- 현재 최고 입찰액과 입찰자
- 경매 및 상점 종료 시각
- 라운드, 판매자 순서
- READY 상태
- 랜덤 결과와 랜덤 시드
- 권투 체력·스태미나·승자

휴대폰은 “버튼을 눌렀다”는 요청만 보내며 결과를 직접 계산하지 않는다.

| 값 | 충실 재현 프리셋 |
|---|---:|
| 아이템 선택 시간 | 20초 [데모 씬 확인] |
| 경매 전체 시간 | 50초 [데모 씬 확인] |

## 4. 한 판의 전체 흐름

```text
방 생성/참가
  → 전원 READY
  → 시작 현금 $2,000 지급
  → 판매자 순서 무작위 결정
  → ROUND 1
      → 판매자 A: 3개 중 1개 선택
      → A의 아이템 경매
      → 낙찰 및 가치/조항 공개
      → 판매자 B, C ... 같은 흐름
      → MARKET / SHOP 60초
          → 아이템 선택 판매 또는 보유
          → 카드 구매
          → 필요하면 현재 누적 가격으로 리롤
          → READY
  → 설정된 마지막 ROUND까지 반복
  → 마지막 MARKET / SHOP
  → 최종 현금 순위
  → 결과·하이라이트·재경기
```

### 라운드와 손(hand)의 용어

- **라운드:** 모든 플레이어가 한 번씩 판매한 뒤 상점까지 끝나는 큰 단위
- **손/경매:** 판매자 한 명이 물건 한 개를 올려 낙찰되는 작은 단위
- 조항의 “1 round”와 “1 hand”는 원문 의미를 데이터에서 구분해야 한다.
- 화면에는 한국어로 각각 `1라운드`, `경매 1회`라고 표시해 오해를 막는다.

## 5. 현장 플레이 운영 방식

### 5.1 공용 화면이 없는 문제의 해결

모든 휴대폰에 같은 공개 정보를 동시에 반복 표시한다.

- 현재 판매자
- 3D 아이템
- 아이템명과 시대
- 남은 시간
- 최고 입찰액
- 최고 입찰자
- 방금 누가 얼마를 입찰했는지
- 낙찰 결과
- 현재 라운드와 판매 순서

개인 정보만 각자 다르게 보인다.

- 판매자: 실제 시장가, 조항 1, 조항 2
- 구매자: 실제 시장가 `?`, 조항 1 `?`, 조항 2 `?`
- 본인 현금
- 본인 인벤토리
- 본인 카드
- 본인이 지정해야 하는 카드 대상 선택창

### 5.2 실제 대화

- 마이크 권한을 요청하지 않는다.
- 음성 데이터는 전송·저장하지 않는다.
- 경매 중 누구나 자유롭게 말하고 협상한다.
- 판매자는 진실을 말해도 되고, 거짓말하거나 일부만 말해도 된다.
- 구매자는 질문, 압박, 공모, 허세를 할 수 있다.
- 게임은 말의 진위를 판정하지 않는다.

### 5.3 “입을 막는” 조항의 현장 처리

원작의 입 막기 효과는 실제 대화에 직접 적용한다.

- 대상자 휴대폰 전체에 붉은 테이프 띠와 `이번 경매에는 말할 수 없습니다` 표시
- 대상자 이름 옆에 🤐 공개 아이콘
- 다음 경매가 끝날 때까지 유지
- 음성 감지는 하지 않고 참가자들이 서로 확인
- 텍스트 채팅 자체가 없으므로 우회 채팅도 불가능
- 표정과 제스처는 허용한다. 원작의 사회적 재미를 살린다.

## 6.1 방 생성과 참가

### 방장 화면

- `방 만들기`
- 닉네임
- 색상/간단한 얼굴 아이콘
- `초대 링크 복사`

- QR 스캔 또는 링크 열기
- 방 코드 입력
- 닉네임 입력
- 색상 선택
- `참가`

### 로비 규칙

- 3명 이상일 때만 시작 가능
- 최대 6명
- 닉네임 중복 불가
- 방장은 시작 전 플레이어 추방 가능
- 기본 모드는 `원작 재현 모드`
- 원작 재현 모드에서는 시작 현금, 씬 기본 5라운드, 누적 리롤 가격 등 검증 프리셋을 사용한다.
- 개발·테스트 모드에서만 값을 변경할 수 있다.

## 6.2 경기 시작

서버가 다음을 한 번에 결정한다.

1. 각 플레이어 현금 `$2,000`
2. 판매 순서 무작위 배정
3. 라운드 번호 `현재/설정 수`
4. 카드 사용 제한 초기화
5. 첫 판매자 지정
6. 비공개 아이템 후보 생성

모든 휴대폰에 판매 순서가 3초간 표시된다.

```text
ROUND 1 / 6
판매 순서
1. 민수  2. 지연  3. 태호  4. 수빈
첫 판매자: 민수
```

---

## 6.3 판매자의 아이템 선택

판매자의 휴대폰에만 후보 3장이 표시된다.

각 후보 카드:

- 회전 가능한 3D 미리보기
- 아이템명
- 시대
- 예상 가격 범위
- 선택 전 공개되는 조항 정보는 영상 기준 UI와 맞추되, 최종 구현 전 재검증
- `판매하기` 버튼

다른 플레이어 화면:

```text
민수가 판매할 물건을 고르는 중…
남은 시간 00:18
지금부터 민수의 표정을 잘 보세요.
```

시간 내 선택하지 않으면 서버가 후보 중 하나를 무작위 선택한다.

선택이 끝나면 판매자에게만 다음 비공개 장부를 보여준다.

```text
실제 시장가: $720
조항 1: 상점 판매 시 +30%
조항 2: 구매자는 다음 경매 동안 말할 수 없음
```

판매자는 이 화면을 아래로 접어 3D 아이템을 크게 보거나 다시 열 수 있다.

## 6.4 경매 시작

### 구매자에게 공개되는 정보

- 3D 아이템
- 아이템명
- 시대
- 시장가 `?`
- 조항 1 `?`
- 조항 2 `?`
- 현재 최고 입찰액
- 최고 입찰자
- 남은 시간

### 판매자에게 추가되는 정보

- 실제 시장가
- 조항 1 전문
- 조항 2 전문
- 판매자는 입찰 버튼 대신 `장부 열기/접기`

### 입찰

휴대폰 하단 고정 영역:

```text
내 현금 $1,850
현재 최고가 $300 · 지연

[-50]  내 제안 $350  [+50]
       [입찰하기]
```

- 금액은 `$50` 단위 [데모 씬 확인]
- 기본 제안은 `현재 최고가 + $50`
- `+50`, `+100`, `+250` 빠른 선택 제공
- 현금보다 큰 금액은 선택 불가
- 판매자는 자기 물건에 입찰 불가
- 입찰 확정은 서버가 수신한 순서대로 처리
- 같은 밀리초에 들어와도 서버 이벤트 시퀀스로 한 명만 먼저 인정
- 뒤늦게 도착한 입찰은 최신 최고가보다 높을 때만 인정
- 성공 시 전원 진동 20ms, 최고 입찰자 화면은 금색
- 추월당한 플레이어는 진동 50ms와 붉은 테두리

### 실제 대화 타이밍

- 경매 시작과 동시에 자유 대화
- 마지막 10초에는 시계 진동/점멸
- 마지막 3초는 매초 짧은 효과음과 진동
- 자동 연장은 원작 확인 전 넣지 않는다.

### 카드 사용

- 화면 오른쪽 아래 `카드` 버튼
- 누르면 보유 카드가 아래 시트로 펼쳐짐
- 사용할 수 없는 카드는 회색 처리하고 이유 표시
- 대상 지정 카드면 플레이어 목록 → 확인 → 서버 판정
- 카드 사용 결과는 필요한 범위만 공개
- 조항으로 카드 사용이 막힌 플레이어는 버튼에 자물쇠 표시

## 6.5 낙찰과 공개

시간이 끝나면 서버가 입찰을 잠근다.

### 1단계: 낙찰

모든 화면:

```text
낙찰!
지연 → $650
```

- 구매자 현금에서 낙찰가 차감
- 판매자 현금에 낙찰가 추가
- 아이템 소유권을 구매자에게 이전

### 2단계: 진실 공개 카드

원작의 영수증/낡은 종이 느낌을 기능적으로 재현한다.

```text
GOLDEN EGG · Medieval Era
Sold For       $650
Market Price   $110

Clause 1
상점에 팔 때 33% 확률로 가치 3배,
실패하면 가치 1/3

Clause 2
보유 중 매 라운드 50% 확률로
$150 획득 또는 $150 손실

Seller  민수
Buyer   지연
```

- 모든 참가자에게 동일 공개
- 8초 자동 노출
- `확인`을 누르면 축소되지만 다음 단계는 전원 동기화
- 공개 값과 효과 적용 결과는 이벤트 로그에 남김

### 3단계: 즉시 조항 처리

처리 순서를 고정한다.

1. 거래 성립
2. 판매자 대상 즉시 효과
3. 구매자 대상 즉시 효과
4. 카드 제거·금전 이동
5. 권투 등 별도 이벤트
6. 다음 경매용 지속 상태 등록
7. 결과 로그 공개

두 조항이 충돌하면 `priority`와 `clauseId` 순서로 처리한다. 같은 랜덤 카드 제거 효과가 두 번 발동하면 첫 제거 후 남은 카드 중 다시 추첨한다.

## 6.6 권투 조항

원작에 권투 결투가 실제 존재하므로 삭제하지 않는다. 다만 PC 1인칭 조작을 두 사람의 휴대폰 터치 조작으로 바꾼다.

### 참가자

- 판매자와 구매자만 조작
- 다른 플레이어는 자기 휴대폰에서 체력바와 3D/2D 중계 관전

### 모바일 조작 [현장 변환]

- 왼쪽 화면 탭: 왼손 잽
- 오른쪽 화면 탭: 오른손 잽
- 좌우 동시 길게 누르기: 가드
- 아래에서 위로 스와이프: 강공격
- 연속 공격 시 스태미나 감소
- 가드 중 이동·공격 불가

### 판정

- 서버가 체력, 스태미나, 공격 쿨다운을 판정
- 20초 제한 [데모 씬 확인]
- KO 또는 시간 종료 시 체력이 높은 쪽 승리
- 원작 조항대로 승자가 아이템과 돈을 모두 가져감
- 동점이면 5초 연장, 그래도 동점이면 서버 시드 추첨이 아니라 피해량 우선

권투를 실제 몸싸움으로 바꾸면 안전 문제가 생기므로 하지 않는다.

## 6.8 시장 및 상점

원작 화면은 하나지만 모바일에서는 같은 기능을 세로 스크롤 3구역으로 재배치한다.

### 상단 고정 바

```text
ROUND 3/6   00:57   SHOP   $4,010   [READY]
```

- 왼쪽: 라운드
- 중앙: 남은 시간
- 오른쪽: 현재 현금
- READY는 항상 오른쪽 상단
- READY 후 다시 누르면 UNREADY
- 전원 READY면 3초 카운트 후 조기 종료
- 시간이 끝나면 미준비자도 자동 READY

### 구역 A: INVENTORY

원작처럼 2×2, 총 4칸.

각 아이템 카드:

- 썸네일/3D 아이콘
- 아이템명
- 시대
- 현재 계산된 시장가
- 조항 1
- 조항 2
- 지속 상태 배지
- `SELECT`

빈 칸은 `EMPTY`로 표시한다.

`SELECT`를 누르면 카드에 빨간 체크가 생기고 우측 영수증이 아니라 모바일 하단의 `CHECKOUT` 바에 담긴다. 다시 누르면 선택 취소된다.

### 구역 B: CHECKOUT

화면 하단 고정 접이식 영수증:

```text
CHECKOUT 3 items
기본 시장가        $1,470
조항 보너스          $210
시대 보너스          $790
-------------------------
TOTAL              $2,470
              [SELL]
```

- 각 항목별 금액을 따로 표시
- `SELL` 전에는 실제 판매가 확정되지 않음
- 랜덤 조항이 있으면 예상 범위 대신 `결과는 판매 시 결정` 표시
- SELL을 누르면 서버가 랜덤과 보너스를 계산
- 판매 완료 아이템은 인벤토리에서 제거
- 돈을 즉시 추가
- 영수증에 계산 근거를 5초 표시
- 선택하지 않은 아이템은 다음 라운드까지 보유

### 시대 보너스

원작에서 같은 시대 아이템 묶음 판매 시 `Era Bonus`가 붙는 것은 확인됐다. 공개 영상으로 정확한 계수는 확정되지 않았다.

따라서 구현은 다음 인터페이스를 사용한다.

```ts
calculateEraBonus(selectedItems, clauseContext): {
  matchedEra: Era | null;
  matchedCount: number;
  amount: number;
  breakdown: string[];
}
```

계수 확정 전에는 원작 재현 빌드에서 개발자 플래그로 잠근다. 임의의 `+20%` 같은 수치를 실제 원작 값이라고 표기하지 않는다.

### 구역 C: BUY CARDS

원작처럼 무작위 카드 3장을 가로로 표시한다.

카드:

- 이름
- 큰 픽토그램
- 가격
- `BUY`

카드를 탭하면 바로 사지 않고 설명 노트가 열린다.

```text
CLAUSE INSIDER
$300

판매자가 파는 아이템의 조항을 확인합니다.

[닫기]                  [BUY $300]
```

구매 성공:

- 돈 차감
- 카드 인벤토리에 추가
- 구매한 상점 칸은 `EMPTY`
- 다른 플레이어의 상점 제시는 변하지 않음

현금 부족, 카드 한도 초과, 상점 종료 후 요청은 서버가 거부한다.

## 6.9 리롤 시스템

원작의 누적 리롤 비용을 그대로 기능화한다.

### 기본 동작

1. 플레이어가 현재 표시된 `REROLL $비용`을 누름
2. 확인 팝업은 생략하고 버튼을 0.5초 길게 눌러 확정
3. 서버가 현재 리롤 비용을 차감
4. 현재 남은 카드와 EMPTY 칸을 포함해 3칸 모두 새 카드로 교체
5. 카드 셔플 애니메이션 0.6초
6. 리롤 횟수 `shopRerollCount` +1

### 규칙

- 한 상점 단계에서 여러 번 가능
- 첫 가격 `$100`, 성공할 때마다 다음 가격 `+$100`
- 돈이 현재 리롤 비용보다 적으면 비활성
- 상점 종료 1초 전부터 요청 잠금
- 플레이어별 상점 목록과 리롤은 독립
- 산 카드는 리롤로 사라지지 않음
- 리롤 이전에 사지 않은 제시 카드만 교체
- 동일 카드가 새 목록에 다시 나오는 것은 카드 풀 가중치가 허용하면 가능

### 조항과 연동

확인된 조항 중 `상점에서 카드를 리롤할 때마다 아이템 가격 +10%`가 있다.

- 리롤 성공 시 해당 아이템마다 누적 스택 +1
- 판매 시 `기준가 × (1 + 0.10 × 스택)` 계산
- 아이템을 여러 라운드 보유해도 스택 유지
- 아이템을 판매하면 스택 소멸
- 리롤 비용 할인을 주는 카드가 적용되면 실제 차감액만 줄고, 성공 횟수는 여전히 +1

### 네트워크 중복 방지

각 요청은 `requestId`를 포함한다. 같은 요청이 재전송되면 돈을 다시 차감하지 않고 첫 결과를 반환한다.

## 6.10 마지막 상점과 결과

설정된 마지막 라운드의 모든 경매가 끝나면 상단 라운드 대신 `GAME COMPLETED`가 표시된다. 마지막 시장/상점에서도 플레이어는 인벤토리 판매와 카드 확인을 마친 뒤 READY를 누른다.

최종 순위:

1. 현금이 많은 순서
2. 동점이면 보유 아이템의 현재 확정 시장가 합
3. 그래도 동점이면 공동 우승

결과 화면:

- 우승자
- 최종 현금
- 가장 큰 이익 거래
- 가장 큰 손해 거래
- 최고가 낙찰
- 가장 많이 거짓말한 사람은 시스템이 판정할 수 없으므로 투표형 재미 항목으로만 제공
- `같은 멤버로 재경기`

마지막 카드 구매는 승패에 도움이 없을 수 있으므로 원작 UI는 유지하되 `마지막 상점입니다`를 표시한다.

바텀시트 높이 75%. 선택 아이템과 계산식을 모두 보여주고 SELL은 화면 하단 고정.

## S14. 카드 상세

카드 이름, 가격, 효과, 사용 가능 시점, 대상, 1회용 여부를 표시한다. BUY는 우측 하단.

## S15. 리롤

버튼을 0.5초 누르는 동안 원형 진행 표시. 완료 후 카드 세 장이 뒤집히며 교체된다. 잔액과 조항 누적이 즉시 갱신된다.

## S16. READY 대기

```text
준비 완료 3/4
민수 ✓  지연 ✓  수빈 ✓  태호 …

[UNREADY]
```

준비 후에도 다른 사람을 기다리는 동안 인벤토리와 카드 설명은 읽을 수 있지만 구매·판매는 잠근다. UNREADY를 누르면 다시 거래 가능하다.

## S17. 최종 결과

순위, 현금, 거래 하이라이트, 재경기 버튼.

### 조항 조합 제한

공개 자료에서 “모든 조합이 가능한지”는 확인되지 않았다. 서버에 다음 금지 규칙을 둘 수 있게 만든다.

```ts
type ClauseDefinition = {
  id: string;
  trigger: ClauseTrigger;
  effect: ClauseEffect;
  priority: number;
  incompatibleWith: string[];
  evidence: "confirmed" | "locked";
};
```

출시 전 원작에서 실제 동시 출현한 조합을 계속 수집하되, 확인되지 않은 조합을 임의로 금지하지 않는다.

### 가격 계산 순서

정확한 원작 연산 순서는 공개 화면만으로 확정할 수 없으므로 다음 순서를 엔진 정책으로 분리한다.

1. 현재 시장가
2. 라운드별 고정 증감
3. 리롤·카드 수·빈 슬롯 등 누적 퍼센트
4. 상점 판매 +10%/+30%
5. 확률 3배 또는 1/3
6. 시대 보너스
7. 체크아웃 `$500` 초과 보너스
8. 정수 반올림

원작 로그로 순서가 확인되면 정책 배열만 변경한다. UI 영수증은 실제 서버 계산 순서대로 줄을 표시한다.

## 10. 카드 상점—확인 범위

### 실제 화면에서 확인한 구조

- 카드 제시 3칸
- 각 카드의 이름, 아이콘, 가격, BUY
- 선택 카드의 DESCRIPTION 노트
- 보유 카드 영역
- `$100`부터 매회 `$100` 상승하는 리롤
- 구매한 자리는 EMPTY

### 카드 구현 원칙

- 카드 이름만 보였다고 효과를 창작하지 않는다.
- MVP 공개 테스트에서는 `Clause Insider`, `Robin Hood`처럼 효과가 확인된 카드만 활성화한다.
- 다른 카드는 데이터에 `enabled: false`로 두고 상점 추첨에서 제외한다.
- 실제 효과가 영상 결과, 공식 패치 노트, 게임 화면 중 두 곳 이상에서 확인되면 활성화한다.
- 카드 설명에는 `사용 가능 단계`, `대상`, `효과`, `소모 여부`를 반드시 표시한다.

```ts
type ActionCardDefinition = {
  id: string;
  name: string;
  price: number;
  timing: "auction_start" | "auction_live" | "before_reveal" | "shop";
  target: "self" | "seller" | "buyer" | "opponent" | "none";
  effect: CardEffect;
  consumable: boolean;
  enabled: boolean;
  evidenceNote: string;
};
```

## 11. 실제 같은 3D 아이템 표현

## 11.1 목표 품질

아이템은 장난감 아이콘이 아니라 실물 경매품처럼 보여야 한다.

- 물리 기반 렌더링(PBR)
- 금속, 유리, 도자기, 가죽, 종이 재질 분리
- 표면의 미세 흠집, 먼지, 산화, 손때
- 중립적인 스튜디오 HDR 조명
- 바닥 접촉 그림자
- 천천히 자동 회전
- 손가락으로 자유 회전·확대
- 낙찰 시 망치 충격에 맞춘 짧은 카메라 흔들림

중요: 품질은 사실적으로 만들되, 모델 자체는 원작에서 추출하지 않고 새로 제작한다.

## 11.2 모바일 자산 예산

아이템 하나:

- LOD0: 25k~50k triangles
- LOD1: 10k~20k triangles
- 텍스처: 1024px 기본, 중요한 영웅 아이템만 2048px
- BaseColor, Normal, ORM 묶음
- KTX2/Basis 압축
- GLB + Draco 또는 Meshopt
- 초기 다운로드는 현재 경매 아이템 1개만
- 다음 후보 모델은 Wi-Fi에서만 백그라운드 프리로드

저사양 모드:

- 실시간 그림자 끄기
- 30fps 상한
- 반사 품질 절반
- 3D 실패 시 미리 렌더한 360도 스프라이트 사용

## 11.3 정보 공정성

- 같은 아이템 인스턴스는 모든 휴대폰에서 같은 모델과 외형

- 시각적 품질이 숨은 가치를 누설하지 않도록 렌더 파라미터를 고정

- 판매자 선택 중 끊김: 시간 종료 시 자동 선택
- 입찰 중 끊김: 기존 최고 입찰은 유지
- 최고 입찰자가 끊겨도 낙찰 책임은 유지
- 상점 중 끊김: 미선택 아이템은 보유, READY 자동 처리
- 60초 이상 이탈: 봇이 입찰하지 않고 최소 행동만 수행

### 현금

- 음수 시장가와 조항 손실이 존재하므로 현금 음수 가능 여부를 별도 정책으로 둔다.
- 입찰은 현재 사용 가능한 현금보다 높게 할 수 없다.
- 낙찰 직전 다른 효과로 돈이 줄어도 서버가 거래 순서를 고정해 이중 지출을 막는다.

### 인벤토리 4칸

- 빈 칸이 없으면 추가 낙찰을 막는지, 임시 5번째 칸을 허용하는지 원작 확인 필요
- 검증 전 가안: 낙찰 물건은 `pendingOverflow`에 넣고 다음 시장에서 강제 정리
- 원작 재현 빌드 출시 전 반드시 실제 동작 확인 항목으로 남긴다.

### 랜덤

- 서버 시드 기반
- 결과 화면에는 시드가 아니라 결과만 공개
- QA 로그에는 시드, 호출 순서, 확률 테이블 저장
- 동일 요청 재전송으로 랜덤을 다시 뽑지 않음

### READY 경합

- 전원 READY가 된 시점부터 3초 유예
- 유예 중 한 명이 UNREADY면 종료 취소
- 상점 시간이 끝났으면 UNREADY 불가

## 15. 연출·사운드·진동

공용 화면이 없으므로 모든 휴대폰의 연출이 동일 시각에 시작돼야 한다.

- 서버가 `animationStartsAt`을 미래 300ms 시점으로 전달
- 각 기기는 해당 시간에 낙찰 망치·카드 뒤집기 실행
- 기기 무음 모드에서도 진동과 시각 효과로 전달
- 효과음 볼륨 기본 60%, 배경음 20%
- 술자리에서 소리가 겹치지 않게 한 기기만 `대표 사운드`로 지정할 수 있음
- 대표 사운드는 음성 채팅이 아니라 효과음 중복 방지 옵션

## 19. 한 판 플레이 예시

1. 네 명이 QR로 방에 들어와 READY를 누른다.
2. 모두 `$2,000`을 받고 민수가 첫 판매자가 된다.
3. 민수만 후보 3개를 보고 Golden Egg를 선택한다.
4. 민수 화면에는 실제 가치 `$110`과 위험한 조항 2개가 보인다.
5. 다른 세 명의 화면에는 Golden Egg, Medieval Era, 물음표 3개만 보인다.
6. 민수는 실제 대화로 “이거 최소 700은 된다”고 주장한다.
7. 지연과 태호가 `$50` 단위로 경쟁하고 지연이 `$650`에 낙찰받는다.
8. 모든 휴대폰에 실제 가치 `$110`과 조항이 공개된다.
9. 구매자 침묵 조항이 있다면 지연에게 테이프 화면이 뜨고 다음 경매 동안 말하지 않는다.
10. 네 명 모두 판매를 끝내면 60초 SHOP이 열린다.
11. 지연은 Golden Egg를 지금 팔지 않고 보유한다.
12. 카드 3장을 보고 마음에 들지 않아 현재 누적 비용을 내고 리롤한다.
13. 리롤 연동 조항이 붙은 보유 아이템은 가격 스택 +1이 된다.
14. 모두 READY를 눌러 다음 라운드로 이동한다.
15. 이 과정을 설정된 라운드 수만큼 반복하고 최종 현금 1위가 승리한다.

## 20. 제작 결론

가장 적합한 형태는 “각자 휴대폰이 개인 장부이자 입찰기이고, 실제 공간이 음성 채팅방 역할을 하는 것”이다.

핵심 제작 판단:

- 전체 3D 게임을 스트리밍하지 않는다.
- 물건만 사실적인 3D로 표시한다.
- 경매와 상점은 빠른 HTML 터치 UI로 만든다.
- 서버가 모든 돈·랜덤·타이머를 판정한다.
- 원작에서 확인된 29개 아이템과 25개 조항만 기본 풀에 넣는다.
- 창작 조항 55개는 별도 확장 모드로도 기본 제공하지 않는다.
- 카드 효과와 시대 보너스처럼 덜 확인된 부분은 검증 전 잠근다.
- 유일한 본질적 변경은 온라인 음성 채팅을 현장 실제 대화로 바꾸는 것이다.

이 사양으로 만들면 공용 화면 없이도 원작의 정보 비대칭, 거짓말, 실시간 입찰, 상점 판단, 리롤, 조항 폭발, 권투, 최종 현금 경쟁을 휴대폰 웹에서 거의 같은 흐름으로 재현할 수 있다.
