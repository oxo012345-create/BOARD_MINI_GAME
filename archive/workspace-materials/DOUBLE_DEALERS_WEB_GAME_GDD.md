문서 버전: 0.1

> 이 문서는 《Double Dealers》의 공개된 핵심 재미를 분석해, 웹에서 구현 가능한 독립 게임으로 재설계한 제작 명세서다. 게임명, 로고, 캐릭터, 3D 모델, UI, 문구, 고유 아이템과 카드 효과를 그대로 복제하지 말고 별도의 세계관과 아트로 제작한다.

## 1. 한눈에 보는 결론

### 추천 기술

| 영역 | 선택 | 선택 이유 |
|---|---|---|
| 클라이언트 | TypeScript + Babylon.js + Vite | 웹 네이티브 3D, WebGL2/WebGPU 지원, 빠른 로딩 최적화 가능 |
| UI | React + Zustand | 로비·상점·인벤토리처럼 UI가 많은 게임에 적합 |

| 실시간 음성 | LiveKit Cloud로 시작 | WebRTC 직접 구축보다 빠르고 안정적이며, 음소거·볼륨·권한 관리 제공 |
| DB | PostgreSQL | 계정, 재화, 소유 아이템, 전적, 거래 원장을 안전하게 저장 |
| 캐시/세션 | Redis | 룸 목록, 매치메이킹, 접속 상태, 레이트 리밋 처리 |
| 파일/CDN | Cloudflare R2 + CDN | 3D 모델, 텍스처, 오디오를 저렴하게 배포 |
| 인증 | 게스트 계정 + 이메일/Google/Discord 연동 | 진입 장벽을 낮추고 이후 계정 보호 가능 |
| 운영 도구 | Sentry + OpenTelemetry + Grafana/Better Stack | 클라이언트 오류, 서버 지연, 매치 이탈 추적 |
| 배포 | MVP: Fly.io 또는 Render / 정식: AWS ECS 또는 GCP Cloud Run | 초기 비용 절약 후 트래픽 증가에 따라 확장 |

### 추천하지 않는 1차 선택

- **Unity WebGL**: 기존 Unity 인력이 있다면 가능하지만 초기 다운로드, 메모리 사용량, 모바일 브라우저 대응, HTML UI 및 음성 연동 비용이 커진다.
- **Phaser**: 2D 게임에는 훌륭하지만 이 프로젝트의 3D 경매장 연출에는 적합하지 않다.
- **순수 Three.js**: 렌더링은 강력하지만 게임용 씬, 에셋, 입력, 애니메이션, 충돌 관련 기반 기능을 더 많이 직접 구성해야 한다.
- **P2P를 게임 판정에 사용**: 방장 이탈과 조작에 취약하다. 음성은 WebRTC, 돈·입찰·카드·승패 판정은 권위 서버가 담당해야 한다.

## 2. 게임 정의

### 장르

- 3~6인 온라인 파티 게임
- 실시간 경매 + 블러핑 + 협상 + 가벼운 전략
- 1판 18~25분
- 권장 이용 환경: 데스크톱 Chrome, Edge, Firefox, Safari 최신 2개 버전
- 모바일은 초기 버전에서 관전 또는 로비만 지원하고, 정식 플레이는 2차 목표로 둔다.

### 핵심 한 문장

판매자만 진짜 가치를 아는 물건을 말로 포장하고, 구매자는 표정·말·입찰 흐름을 읽어 돈을 벌어야 한다.

### 플레이 감정 곡선

1. **호기심**: 이번 물건과 조항이 무엇인지 탐색한다.
2. **의심**: 판매자의 설명과 행동을 분석한다.
3. **흥분**: 제한 시간 안에 입찰 경쟁이 급격히 올라간다.
4. **폭로**: 낙찰 직후 진짜 가치와 조항이 공개된다.
5. **웃음/배신감**: 예상 밖의 손익이 발생한다.
6. **복수 계획**: 카드와 다음 판매 턴으로 판을 뒤집는다.

### 차별화 방향

원작과 외형을 그대로 따라가기보다 다음 요소를 독자적으로 강화한다.

- 증기기관 시대의 괴짜 발명품 경매장이라는 별도 세계관
- 말하지 못하는 플레이어를 위한 빠른 문구 휠과 감정표현
- 관전자도 참여 가능한 “시장 전망 투표”
- 한 판마다 공개되는 시장 트렌드로 아이템 가치 변동
- 접근성 높은 평면 UI와 저사양용 2D 모드

## 3. 핵심 게임 규칙

### 3.1 기본 수치

| 항목 | 기본값 |
|---|---:|
| 인원 | 3~6명 |
| 시작 현금 | 1,000 코인 |
| 시작 아이템 후보 | 플레이어당 3개 |
| 전체 라운드 | 3라운드 |
| 한 라운드 경매 수 | 현재 플레이어 수만큼 |
| 판매 준비 | 20초 |
| 소개/협상 | 45초 |
| 최종 입찰 | 15초 |
| 폭로 연출 | 8초 |
| 시장 단계 | 60초 |
| 카드 손패 제한 | 3장 |
| 파산 기준 | 현금과 청산 가능 자산 합계가 0 이하 |

실제 밸런스는 플레이테스트 결과에 따라 서버 설정으로 바꿀 수 있어야 한다.

### 3.2 한 판의 흐름

1. 로비에서 3~6명이 준비한다.
2. 서버가 시드와 시작 순서를 확정한다.
3. 각 플레이어에게 비공개 아이템 후보 3개를 배분한다.
4. 첫 판매자가 아이템 하나를 고른다.
5. 판매자만 기본 가치와 숨은 조항 2개를 확인한다.
6. 판매자는 음성 또는 빠른 문구로 물건을 설명한다.
7. 구매자들은 공개 호가로 입찰하거나 철회한다.
8. 시간이 끝나면 최고 입찰자가 낙찰받는다.
9. 서버가 진짜 가치와 즉시 발동 조항을 공개하고 정산한다.
10. 다음 플레이어가 판매자가 된다.
11. 모든 플레이어가 한 번씩 판매하면 시장 단계로 이동한다.
12. 플레이어는 보유 아이템을 즉시 매각하거나 보유하고, 카드 상점에서 카드를 산다.
13. 3라운드가 끝나면 모든 자산을 최종 청산한다.
14. 최종 순자산이 가장 높은 플레이어가 승리한다.

### 3.3 경매 규칙

- 입찰은 현재 최고가보다 최소 10 코인 높아야 한다.
- 빠른 입찰 버튼은 `+10`, `+50`, `+100`, `직접 입력`을 제공한다.
- 마지막 3초에 새 입찰이 들어오면 3초를 다시 부여하며 최대 3회 연장한다.
- 판매자는 자기 물건에 입찰할 수 없다.
- 구매자는 보유 현금을 넘는 입찰을 할 수 없다.
- 동률은 서버에 먼저 도착한 유효 입찰이 우선한다.
- 모든 입찰은 서버 시간이 기준이며 클라이언트 애니메이션은 결과를 표현만 한다.
- 낙찰 대금은 구매자에게서 차감되고 판매자에게 지급된다.
- 조항 정산으로 판매 대금이 바뀌더라도 서버의 하나의 트랜잭션 안에서 처리한다.

### 3.4 정보 공개 원칙

| 정보 | 판매자 | 구매자 | 관전자 |
|---|---|---|---|
| 아이템 이름/외형 | 공개 | 공개 | 공개 |
| 카테고리 | 공개 | 공개 | 공개 |
| 진짜 기본 가치 | 공개 | 비공개 | 비공개 |
| 숨은 조항 2개 | 공개 | 비공개 | 비공개 |
| 현재 최고 입찰 | 공개 | 공개 | 공개 |
| 각 플레이어 현금 | 공개 권장 | 공개 권장 | 공개 |
| 개인 카드 손패 | 본인만 | 본인만 | 비공개 |
| 시장 트렌드 | 공개 | 공개 | 공개 |

현금을 공개하면 대화와 압박이 풍부해지고 계산도 쉬워진다. 하드코어 규칙에서는 현금을 비공개로 바꿀 수 있다.

### 3.5 최종 점수

`최종 점수 = 현금 + 최종 청산가 + 세트 보너스 + 카드 보너스 - 부채 - 벌금`

동점 처리 순서:

1. 현금이 많은 플레이어
2. 보유한 희귀 아이템 수
3. 전체 경매에서 더 적은 돈을 쓴 플레이어
4. 그래도 같으면 공동 승리

## 4. 아이템 시스템

### 4.1 아이템 데이터 구조

```ts
type AuctionItem = {
  id: string;
  nameKey: string;
  category: "ART" | "MACHINE" | "RELIC" | "LUXURY" | "ODDITY";
  rarity: "COMMON" | "UNCOMMON" | "RARE" | "LEGENDARY";
  baseValue: number;
  volatility: number;
  clauseIds: [string, string];
  visualAssetId: string;
  revealSoundId: string;
  tags: string[];
};
```

- 아이템 가치는 서버가 생성하고 판매자에게만 전송한다.
- 같은 외형이라도 가치 범위와 조항 조합이 달라질 수 있다.
- 한 아이템에 서로 모순되는 조항이 붙지 않도록 조합 금지표를 둔다.
- 희귀도는 비주얼의 화려함이지 가치의 정확한 보증이 아니어야 한다.

### 4.3 시장 트렌드

매 라운드 시작 시 2개를 공개한다.

예:

- “박물관 특별전”: 유물 청산가 +25%
- “기계 안전 규제”: 기계 청산가 -20%
- “상류층의 새 유행”: 사치품을 2개 이상 보유하면 각 +80
- “예술품 위작 파동”: 예술품 변동성 2배
- “괴짜 수집가 등장”: 기묘품 중 가장 싼 1개가 +200
- “현금 부족 사태”: 시장에서 즉시 매각 시 -10%, 최종 보유 시 +10%

시장 트렌드는 모든 플레이어에게 공개되어 합리적 추론 재료가 된다.

## 5. 숨은 조항 시스템

### 5.1 조항 설계 원칙

- 조항은 항상 정확한 타이밍 문구를 가진다: `낙찰 즉시`, `시장 단계`, `최종 정산`.
- 판매자에게 유리한 조항, 구매자에게 유리한 조항, 양쪽을 흔드는 조항을 섞는다.
- 무조건 파산시키는 효과보다 선택과 대처가 가능한 효과를 우선한다.
- 조항 1개가 한 플레이어의 전체 자산 30% 이상을 한 번에 날리지 않게 상한을 둔다.
- 처음 3판 동안은 초보자용 조항 12개만 사용한다.

### 5.2 MVP 조항 24종

| 조항 | 공개 시점 | 효과 |
|---|---|---|
| 감정가 보증 | 낙찰 즉시 | 기본 가치가 300 미만이면 구매자에게 차액의 50% 환급 |
| 판매 수수료 | 낙찰 즉시 | 판매자가 낙찰가의 15%를 은행에 지불 |
| 구매세 | 낙찰 즉시 | 구매자가 낙찰가의 10%를 추가 지불, 최대 100 |
| 숨은 후원자 | 낙찰 즉시 | 판매자가 은행에서 100 추가 획득 |
| 파손 배송 | 낙찰 즉시 | 아이템 기본 가치 -25% |
| 완벽한 포장 | 낙찰 즉시 | 아이템 기본 가치 +20% |
| 공동 소유권 | 시장 단계 | 판매자가 해당 아이템 청산 이익의 20% 획득 |
| 되팔기 금지 | 시장 단계 | 이번 시장 단계에는 매각할 수 없음 |
| 긴급 청산 | 시장 단계 | 이번 시장 단계에 반드시 매각 |
| 보험 가입 | 시장 단계 | 청산가가 낙찰가보다 낮으면 최대 120 보상 |
| 유행 선도 | 최종 정산 | 같은 분류 아이템마다 +60 |
| 외로운 걸작 | 최종 정산 | 같은 분류를 하나만 보유하면 +180 |
| 저주받은 소유물 | 라운드 종료 | 보유 중이면 70 지불 |
| 복리 배당 | 라운드 종료 | 보유 중이면 라운드 번호 × 45 획득 |
| 경쟁자의 질투 | 낙찰 즉시 | 2위 입찰자가 50 획득 |
| 낙찰자 지정 기부 | 낙찰 즉시 | 최하위 플레이어에게 80 지급 |
| 가짜 감정서 | 폭로 시 | 표시된 기본 가치가 ±20% 범위로 다시 결정 |
| 진품 인증 | 폭로 시 | 모든 가치 감소 효과를 무효화 |
| 쌍둥이 수집품 | 최종 정산 | 동일 태그 아이템이 있으면 둘 다 +120 |
| 유지비 폭탄 | 시장 단계 | 보유하려면 100 지불, 못 내면 즉시 매각 |
| 판매자의 미련 | 시장 단계 | 판매자가 110을 내고 아이템을 되살 권리 보유 |
| 자선 경매 | 낙찰 즉시 | 낙찰가의 20%가 사라지지만 평판 토큰 1개 획득 |
| 역전 계약 | 최종 정산 | 현재 최하위라면 가치 +250, 아니면 변화 없음 |
| 입단속 계약 | 다음 경매 | 낙찰자는 다음 경매 첫 15초간 빠른 문구 사용 불가. 음성 차단은 하지 않음 |

“입단속 계약”처럼 실제 음성 발화를 막는 규칙은 접근성과 악용 문제가 있으므로 음성을 기술적으로 차단하지 않는다.

### 5.3 조항 조합 금지 예시

- `긴급 청산` + `되팔기 금지`
- `파손 배송` + `진품 인증`
- `유행 선도` + `외로운 걸작`
- `복리 배당` + `긴급 청산`
- `판매자의 미련` + 구매자 소유권을 즉시 제거하는 다른 효과

## 6. 인게임 카드

카드는 시장 단계에서 게임 내 코인으로 산다. 유료 재화로 구매할 수 없다.

### 6.1 카드 규칙

- 카드 상점에는 플레이어마다 무작위 3장이 보인다.
- 라운드당 최대 2장 구매, 손패 최대 3장.
- 반응 카드는 대상 효과가 공개된 후 5초 안에 사용한다.
- 동일 카드의 연속 사용은 제한한다.
- 카드 선택과 결과는 서버가 판정한다.

### 6.2 MVP 카드 20종

| 카드 | 가격 | 사용 시점 | 효과 |
|---|---:|---|---|
| 돋보기 | 120 | 경매 준비 | 조항 하나의 긍정/부정 성향만 확인 |
| 장부 열람 | 160 | 경매 준비 | 기본 가치가 300 이상인지 확인 |
| 시장 소문 | 100 | 경매 준비 | 기본 가치의 가능한 범위를 40% 좁힘 |
| 가짜 하품 | 60 | 협상 | 자신의 이름을 5초간 “관심 없음” 상태로 표시 |
| 대리 입찰 | 90 | 입찰 전 | 설정한 상한까지 서버가 자동으로 +10 입찰 |
| 마지막 한마디 | 100 | 종료 직전 | 경매 시간을 5초 연장. 경매당 1회 |
| 봉인 왁스 | 140 | 판매 준비 | 이번 아이템에 대한 조사 카드 1회를 무효화 |
| 감정사 매수 | 180 | 폭로 직전 | 자신의 낙찰품 가치 감소 1개를 50% 완화 |
| 보험 증권 | 150 | 낙찰 후 | 이번 구매 손실을 최대 150 보전 |
| 차압 명령 | 220 | 시장 단계 | 선두 플레이어의 카드 상점 가격 +30%, 1라운드 |
| 내부자 거래 | 200 | 시장 단계 | 다음 라운드 트렌드 하나를 미리 확인 |
| 품목 독점 | 180 | 시장 단계 | 분류 하나를 지정, 다음 청산가 +10% |
| 급전 대출 | 0 | 언제든 | 250 획득, 최종 정산 때 330 상환 |
| 계약 파기 | 200 | 조항 공개 | 자신에게 적용되는 조항 하나를 취소, 게임당 1회 |
| 반사 도장 | 240 | 대상 카드 공개 | 자신을 겨냥한 카드 효과를 사용자에게 돌림 |
| 경매 방해꾼 | 150 | 협상 | 빠른 입찰 단위를 10초간 +50으로 변경 |
| 공개 감정 | 250 | 협상 | 기본 가치의 하한을 전원에게 공개 |
| 비밀 거래 | 130 | 시장 단계 | 다른 플레이어와 아이템-현금 거래 제안 1회 |
| 보관 창고 | 120 | 시장 단계 | 유지비 또는 보유 페널티 1회 무효 |
| 수집가 명함 | 170 | 최종 정산 | 선택한 태그 아이템당 +50, 최대 +200 |

### 6.3 카드 UX

- 사용 가능한 순간에만 카드가 밝게 활성화된다.
- 대상이 필요한 카드는 플레이어 초상화를 선택한 뒤 확인한다.
- 효과가 큰 카드는 3초짜리 공용 연출과 로그를 남긴다.
- 카드 문구는 `언제 / 누구에게 / 무엇이 / 얼마나` 순서로 작성한다.
- 카드 효과를 처음 본 플레이어는 길게 눌러 예시를 볼 수 있다.

## 7. 상점과 경제

“상점”은 두 종류로 분리한다.

### 7.1 인게임 카드 상점

- 한 판 안에서만 사용하는 전략 카드 판매
- 게임 내 현금으로만 구매
- 매 라운드 갱신
- 승부에 직접 영향
- 유료 결제와 완전히 분리

### 7.2 메타 상점

판매 가능:

- 캐릭터 의상
- 모자, 안경, 콧수염, 장갑
- 경매 패들 스킨
- 승리 포즈
- 감정표현
- 이름표 테두리
- 폭로 시 파티클
- 로비 배경 음악 팩
- 음성 이펙트는 가청성을 해치지 않는 약한 효과만 허용

판매 금지:

- 기본 가치 또는 조항을 더 많이 보는 기능
- 입찰 시간 증가
- 시작 현금 증가
- 카드 슬롯 증가
- 전적을 숨기거나 매치메이킹을 조작하는 기능
- 유료 확률형 능력 아이템

### 7.3 재화

| 재화 | 획득 | 사용 |
|---|---|---|
| 명성 | 플레이 완료, 일일 과제, 시즌 보상 | 기본 코스튬과 감정표현 |
| 티켓 | 현금 구매 또는 시즌 프리미엄 보상 | 프리미엄 코스튬 |
| 게임 코인 | 매치 시작 시 지급, 한 판 종료 시 소멸 | 경매, 카드 상점 |

### 7.4 권장 가격

| 상품 | 권장가 |
|---|---:|
| 소형 액세서리 | 1,100~2,200원 상당 |
| 의상 세트 | 4,900~8,900원 상당 |
| 고급 승리 포즈 | 3,300~5,500원 상당 |
| 시즌 패스 | 9,900원 상당 |
| 광고 제거 | 광고를 도입할 경우 4,900원 |

첫 출시에는 결제 없이 명성 상점만 열고, 유지율이 확인된 뒤 결제를 붙이는 편이 안전하다.

### 7.5 경제 원장

모든 재화 변화는 다음 필드를 가진 append-only 원장에 기록한다.

```text
transaction_id
user_id
currency
delta
balance_before
balance_after
reason_code
match_id / order_id
created_at
idempotency_key
```

클라이언트는 잔액을 직접 변경하지 못한다.

## 8. 화면별 콘티

### S01. 부팅/로딩

- 중앙: 게임 로고와 톱니바퀴가 도는 짧은 애니메이션
- 하단: 에셋 다운로드 진행률, 현재 단계, 취소/재시도
- 최초 접속은 20~30MB 이하의 필수 에셋만 받고 나머지는 백그라운드 로딩
- 8초 이상 걸리면 작은 세계관 문구와 조작 팁 표시

### S02. 최초 진입

- `바로 시작` 게스트 버튼을 가장 크게 배치
- `Google`, `Discord`, `이메일` 로그인은 하단 배치
- 닉네임 생성, 이용약관, 음성 채팅 동의, 만 14세 확인
- 마이크는 이 화면에서 강제 요청하지 않고 음성 설정 진입 때 요청

### S03. 메인 홀

- 중앙: 캐릭터와 경매장 3D 배경
- 좌측 메뉴: 빠른 참가, 방 만들기, 튜토리얼
- 우측 메뉴: 친구, 초대, 일일 과제
- 상단: 프로필, 명성, 티켓, 설정
- 하단: 상점, 옷장, 전적, 시즌
- “빠른 참가”를 첫 행동으로 유도

### S04. 방 만들기

- 방 이름, 공개/비공개, 인원 3~6명
- 라운드 2/3/4, 경매 시간 짧음/보통/김
- 초보자 조항만, 카드 사용 여부, 관전자 허용
- 음성 채팅 `전체`, `눌러 말하기`, `사용 안 함`
- 초대 코드 복사 버튼

### S05. 대기 로비

- 원형 테이블 주변에 플레이어 캐릭터 배치
- 빈 좌석에는 초대 버튼
- 플레이어 카드에 준비 상태, 마이크, 핑 표시
- 방장은 강퇴, 설정 변경, 시작 가능
- 3명 이상이고 전원 준비 시 5초 카운트다운
- 준비 해제 시 카운트다운 취소

### S06. 튜토리얼

3분 안에 끝나는 봇 경매 한 번으로 구성한다.

1. 판매자 시점에서 가치와 조항 확인
2. 빠른 문구로 봇 설득
3. 구매자 시점으로 전환
4. 입찰
5. 폭로와 손익 확인
6. 시장 매각과 카드 구매

설명문보다 실제 클릭을 유도하고, 완료 시 코스튬을 지급한다.

### S07. 라운드 인트로

- 3D 카메라가 테이블을 한 바퀴 돌며 판매 순서 표시
- 중앙 오버레이에 현재 라운드와 시장 트렌드 2개 공개
- 5초 후 경매 준비로 이동
- 멀미 방지 옵션에서는 카메라 이동 없이 페이드 전환

### S08. 판매자 아이템 선택

- 화면 하단에 후보 3개 카드
- 카드에 이름, 분류, 판매자만 보는 진짜 가치와 조항 2개 표시
- 각 카드 위에서 3D 아이템 미리보기 회전
- 20초 내 미선택 시 서버가 무작위 선택
- 선택 후 다시 바꿀 수 있는 3초 확인 단계

### S09. 경매 본 화면

화면 구성:

- 중앙 55%: 경매대와 3D 아이템
- 상단 중앙: 단계명, 남은 시간, 현재 최고가
- 좌우 가장자리: 플레이어 초상화, 현금, 입찰/철회 상태, 마이크
- 우측 하단: `+10`, `+50`, `+100`, 직접 입력, 입찰 버튼
- 좌측 하단: 카드 손패와 빠른 문구 휠
- 하단 중앙: 최근 3개 입찰 로그
- 판매자 화면 우측: 실제 가치와 조항을 적은 비밀 장부

연출:

- 입찰 시 캐릭터가 패들을 들고 코인 소리가 난다.
- 최고 입찰자가 바뀌면 이름표 테두리가 금색으로 점등된다.
- 5초 이하에서 음악이 빨라지되 음성은 묻지 않는다.
- 마지막 입찰 연장 횟수를 점 3개로 표시한다.

### S10. 폭로/정산

1. 아이템에 스포트라이트
2. 진짜 기본 가치 공개
3. 조항 1 공개 및 즉시 정산
4. 조항 2 공개 및 즉시 정산
5. 구매자 손익, 판매자 수익 표시
6. 전체 순위가 옆에서 짧게 갱신

한 번에 숫자가 튀지 않도록 `낙찰가 → 가치 → 조항 → 최종 손익` 순서로 보여준다.

### S11. 시장 단계

- 좌측: 내 보유 아이템 그리드
- 중앙: 선택 아이템의 현재 예상 청산가와 조항
- 버튼: 즉시 매각 / 계속 보유
- 우측: 카드 상점 3칸, 갱신 1회
- 상단: 트렌드, 남은 시간, 현금
- 하단: 플레이어별 자산 추정치. 하드코어 모드에서는 숨김
- 시간 종료 시 선택하지 않은 아이템은 기본적으로 보유

### S12. 최종 정산

- 모든 아이템을 한 개씩 빠르게 청산
- 세트와 카드 보너스를 별도 줄로 표시
- 순위가 오르내리는 애니메이션
- 최종 1위 캐릭터가 중앙 연단에 등장
- `재대결`, `같은 방`, `메인으로` 버튼

### S13. 결과/전적

- 최종 순위, 순자산, 최대 이익 거래, 최대 손실 거래
- “최고의 허풍”, “가장 신중한 구매자” 같은 비경쟁 칭호
- 신고, 친구 추가, 차단은 플레이어 카드 메뉴에 배치
- 재대결 투표는 20초간 유지

### S14. 메타 상점/옷장

- 상점과 옷장을 같은 3D 미리보기 무대에서 전환
- 구매 전 캐릭터 회전, 승리 포즈 재생
- 재화 종류와 최종 가격을 명확히 표시
- 확률형 상품은 사용하지 않는다.
- 구매 API는 중복 요청 방지를 위해 idempotency key 사용

### S15. 설정/접근성

- 마스터/음악/효과/음성 채팅 개별 볼륨
- 플레이어별 음소거와 볼륨
- 눌러 말하기, 음성 감지, 입력 장치
- 색약 팔레트, 큰 글씨, 화면 흔들림, 카메라 이동
- 자막, 효과음 시각화, 빠른 문구
- 저사양 모드, 해상도 배율, 그림자, 파티클

## 9. 아트·카메라·오디오

### 9.1 비주얼 방향

- 1900년대 초 상류층 경매장을 연상시키되 실제 브랜드나 원작 캐릭터는 사용하지 않는다.
- 머리가 크고 몸이 단순한 독자적 실루엣의 3D 캐릭터
- 따뜻한 갈색 목재, 청록색 금속, 황동 포인트
- 표정은 눈썹, 눈, 입, 콧수염 물리 애니메이션으로 과장
- 아이템은 멀리서도 분류가 보이도록 형태와 컬러를 명확히 구분

### 9.2 브라우저용 에셋 예산

| 항목 | 예산 |
|---|---:|
| 초기 다운로드 | 20~30MB |
| 전체 캐시 | 100MB 이하 |
| 캐릭터 1개 | 25k~40k triangles |
| 동시 화면 캐릭터 | 최대 6 |
| 아이템 | 3k~15k triangles |
| 텍스처 | 기본 1K, 얼굴/주요 배경만 2K |
| 드로우콜 | 중간 사양 기준 150 이하 |
| 목표 FPS | 데스크톱 60, 저사양 30 |

glTF/GLB, KTX2/Basis 텍스처, Draco 또는 Meshopt 압축, OGG/Opus 오디오를 사용한다.

### 9.3 카메라

- 기본은 테이블 전체가 보이는 고정 3/4 시점
- 판매자 소개 때만 아이템으로 부드럽게 줌
- 폭로 때 1.5초 이내의 짧은 카메라 연출
- 사용자 입력이 필요한 동안 카메라를 크게 움직이지 않는다.

### 9.4 오디오

- 음성이 핵심이므로 배경 음악은 -20 LUFS 수준으로 낮게 유지
- 입찰, 낙찰, 폭로, 손실의 소리를 서로 명확히 구분
- Opus 음성, 에코 제거, 자동 이득 조절, 노이즈 억제 활성화
- 음성 채팅이 꺼져 있어도 빠른 문구와 핑만으로 플레이 가능해야 한다.

## 10. 서버 구조

### 10.1 전체 구조

```text
Browser Client
  ├─ HTTPS → API Gateway → Auth/Profile/Shop API → PostgreSQL
  ├─ WSS   → Colyseus Game Room → Redis presence/session
  ├─ WebRTC → LiveKit Voice SFU
  └─ HTTPS → Cloudflare CDN/R2 assets
```

### 10.2 권위 서버가 관리할 값

- RNG 시드와 아이템 생성
- 아이템 진짜 가치와 조항
- 플레이어 현금, 자산, 손패
- 입찰 유효성, 최고가, 타이머
- 카드 구매와 사용
- 시장 매각과 조항 적용
- 라운드 전환과 최종 순위
- 재접속 토큰과 자동 행동

클라이언트가 담당할 값:

- 애니메이션 상태
- 카메라, 그래픽 설정
- UI 열림/닫힘
- 음량, 키 바인딩
- 서버 결과를 표현하는 이펙트

### 10.3 게임 상태 머신

```text
LOBBY
 → STARTING
 → ROUND_INTRO
 → SELLER_SELECT
 → NEGOTIATION
 → FINAL_BIDDING
 → REVEAL
 → SETTLEMENT
 → NEXT_SELLER
 → MARKET
 → NEXT_ROUND
 → FINAL_SETTLEMENT
 → RESULTS
 → CLOSED
```

각 상태는 허용 명령 목록을 가진다. 예를 들어 `placeBid`는 `NEGOTIATION`과 `FINAL_BIDDING`에서만 처리한다.

### 10.4 핵심 WebSocket 명령

클라이언트 → 서버:

```text
player.ready
seller.selectItem
auction.placeBid
auction.withdrawIntent
card.buy
card.play
market.sellItem
market.holdItem
trade.propose
trade.accept
emote.send
player.reconnect
```

서버 → 클라이언트:

```text
room.snapshot
phase.changed
timer.synced
auction.bidAccepted
auction.bidRejected
auction.revealed
effect.resolved
wallet.changed
market.updated
match.completed
```

모든 명령에는 `commandId`, `matchId`, `clientSeq`, `sentAt`을 넣는다. 중복 명령은 같은 결과를 반환한다.

### 10.5 타이머

- 서버 monotonic clock이 단일 기준이다.
- 클라이언트는 `serverEndsAt`을 받아 화면만 보간한다.
- 5초마다 시간 오차를 보정한다.
- 서버가 받은 시점이 마감 이전인 유효 명령만 인정한다.
- 브라우저 탭이 백그라운드가 되어도 서버 타이머는 계속 진행한다.

### 10.6 재접속

- 연결 종료 후 60초 동안 좌석 유지
- 15초 이내: 현재 스냅샷을 받고 즉시 복귀
- 15~60초: 자동 행동 적용 후 복귀
- 판매자 미접속: 아이템 무작위 선택, 빠른 문구 없이 경매 진행
- 구매자 미접속: 자동 패스
- 시장 단계 미접속: 기본 보유
- 60초 초과: 봇 대체 또는 기권. 방 설정에 따라 선택

## 12. 보안·치팅·신고

### 보안

- 로그인 쿠키는 Secure, HttpOnly, SameSite 적용
- 비밀번호 직접 저장 대신 검증된 인증 서비스 또는 Argon2id 사용
- 모든 REST 쓰기 요청은 CSRF와 레이트 리밋 적용
- 상점 결제는 결제사 webhook을 서버가 검증한 뒤 지급
- 아이템 가치와 조항은 폭로 전 구매자 클라이언트에 절대 전송하지 않음
- 매치 로그는 조작 탐지와 고객 지원을 위해 30~90일 저장

### 치팅 탐지

- 불가능한 금액의 입찰, 상태에 맞지 않는 카드 사용 거절
- 비정상적으로 빠른 반복 명령 제한
- 다중 계정 담합은 IP만으로 판단하지 않고 반복 거래 패턴 분석
- 클라이언트 시계, 로컬 스토리지, 화면 표시 값을 판정에 사용하지 않음

### 커뮤니티 안전

- 플레이어별 음소거, 차단, 신고
- 닉네임 금칙어와 유니코드 혼동 문자 정규화
- 빠른 문구만 허용하는 안전 모드
- 방장 강퇴는 로비에서만, 게임 중에는 다수결 추방
- 신고 카테고리: 욕설, 혐오, 성적 발언, 방해, 담합, 부적절한 닉네임

## 13. 매치메이킹과 봇

### 빠른 참가

- 지역 → 예상 핑 → 언어 → 초보자 여부 순으로 검색
- 10초 안에 방이 없으면 인접 지역까지 확대
- 20초 안에 3명이 모이지 않으면 봇 포함 여부를 사용자에게 제안
- 파티는 같은 팀이 아니라 같은 방에만 들어가므로 실력 기반 매칭은 느슨하게 적용

### 봇 행동

- 가치를 정확히 아는 치팅 봇을 만들지 않는다.
- 공개 정보, 경매 이력, 랜덤 성향으로 입찰 상한을 계산한다.
- 성격: 신중형, 공격형, 추종형, 허풍형
- 판매 시 실제 가치와 조항에 따라 진실/과장/거짓 문구를 확률적으로 선택
- 봇은 음성 대신 말풍선과 캐릭터 제스처를 사용

## 16. 개발 순서

가장 먼저 “재미 검증용 회색 상자 버전”을 만든다.

1. 4명이 브라우저 4개로 같은 방에 접속
2. 판매자에게만 가치와 조항 표시
3. 실시간 입찰
4. 폭로와 돈 정산
5. 한 라운드 반복
6. 음성 연결

이 상태로 10판을 테스트해 대화가 실제로 발생하는지 확인한 뒤 3D 아트와 상점을 제작한다. 핵심 대화가 재미없으면 고급 그래픽이 문제를 해결하지 못한다.

## 17. 테스트 기준

### 기능 QA

- 동시에 입찰할 때 최고가가 하나로 확정되는가
- 마지막 3초 연장이 정확히 최대 3회인가
- 조항 조합 금지표가 적용되는가
- 카드 반사와 취소가 무한 반복되지 않는가
- 재접속 후 비공개 정보가 올바른 사람에게만 보이는가
- 새로고침으로 카드나 상점 구매가 중복되지 않는가
- 판매자 이탈, 구매자 이탈, 방장 이탈이 처리되는가

### 부하 QA

- 룸 500개 × 6명, 동시 3,000명에서 서버 지연 측정
- WebSocket 메시지 p95 150ms 이하 목표
- 방 생성 p95 2초 이하
- 매치 종료 DB 기록 실패 시 재시도 큐 작동
- 음성은 LiveKit 별도 부하 지표로 관리

### 제품 지표

- 튜토리얼 완료율 70% 이상
- 첫 공개 매치 시작률 60% 이상
- 매치 완주율 80% 이상
- 다음 날 재방문율 D1 25% 이상
- 평균 한 세션 1.8판 이상
- 매치당 음성 또는 빠른 문구 사용 플레이어 70% 이상
- 신고율 100매치당 3건 이하

### 밸런스 지표

- 판매자 평균 이익
- 구매자 평균 낙찰 손익
- 아이템별 평균 낙찰가/기본 가치 비율
- 카드별 구매율과 승률 변화
- 선두 플레이어의 최종 승리율
- 시작 순서별 승률

어떤 카드의 보유 여부가 승률을 8%p 이상 올리면 가격 또는 효과를 우선 검토한다.

## 19. 출시 전 법적 체크

- 《Double Dealers》라는 이름, 로고, 캐릭터, UI 배치, 3D 모델, 음악, 효과음, 문구를 복제하지 않는다.
- “판매자만 가치와 조항을 안다” 같은 추상적인 게임 규칙을 참고하더라도 표현과 콘텐츠는 독자적으로 만든다.
- 원작의 아이템·카드·조항을 실제 플레이에서 추출해 그대로 옮기지 않는다.
- 음성 채팅 개인정보 처리방침과 커뮤니티 가이드라인을 제공한다.
- 미성년자, 결제 환불, 디지털 상품, 확률형 상품 관련 출시 국가 법규를 검토한다.
- 상용 출시 전에는 게임 전문 변호사 또는 변리사의 검토를 받는다.

## 21. 공개 사실과 본 문서의 제안 구분

공식 공개 정보로 확인되는 부분:

- 3~6인
- 플레이어가 돌아가며 판매자가 됨
- 각자 3개 아이템 중 하나를 경매에 선택
- 판매자만 실제 시장 가치와 숨은 조항 2개를 확인
- 실시간 협상과 입찰
- 전원이 판매한 뒤 시장 단계
- 시장에서 즉시 판매 또는 보유 선택
- 시장 단계에서 전략 카드 구매 가능

본 문서가 제작을 위해 새로 제안한 부분:

- 정확한 시작 금액, 라운드 수, 타이머, 연장 규칙
- 모든 아이템, 조항, 카드 이름과 수치
- 시장 트렌드와 세트 보너스
- 상점과 재화
- 기술 스택, 서버 구조, API와 DB
- 화면 콘티, 아트 방향, 제작 일정

따라서 실제 원작의 완전한 복제 명세가 아니라, 확인된 핵심 루프를 기반으로 만든 독립적인 웹게임 설계안이다.
