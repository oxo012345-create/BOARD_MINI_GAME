# 군단 온라인 끊김 수정

2026-11-03. 개인별200기 밸런스는 유지한다. 이번 변경은 온라인 상태 수신·화면 이동·서버 진행 경로다.

## 재현

공개 한판에 독립 쿠키4개로 검증용 팀전 방을 만들고 전군 이동을 반복했다. 사용자의4647번 방에는 참가하거나 명령을 보내지 않았다. 병력이4–20기인 경우에도 폴링 왕복 평균874ms/p951272ms, 같은 참가자의 새 스냅샷 간격 평균1123ms/p951917ms였다. 같은 시간대 Worker 로그의 군단 요청은 CPU수–십여ms에 비해 전체 처리에약0.7–1.4초가 걸렸다. 로컬D1 테스트의 빠른 응답과 실제 공개 서버 응답을 구분해야 한다.

기존 클라이언트는 매 상태를100ms만 보간하고 다음 응답까지 멈췄다. 따라서 그리기30FPS 자체를 유지해도 이동은 대부분의 프레임에서 멈췄다. 대군주/투사체/게임 애니메이션 시각도 수신 시점에 종속됐다. 서버는 요청 하나당 최대6틱만 진행해 느린 DB 응답에서 전체 경기 속도까지 떨어질 수 있었다.

## 변경

- 부모 방 인증 정보와 캐시된 군단 상태를한 번의D1 조회로 읽는다. 쿠키 인증·현재 라운드·고정 좌석 확인 후에만 상태를 반환하거나 명령을 처리한다. 인증 결과를 프로세스 메모리에 캐시하지 않는다.
- 원자적 잠금의RETURNING으로 체크포인트와 대기 명령을 함께 읽는다. 잠금 획득 후 추가 조회를 없앴다. 이미 다른 요청이 잠금을 잡은 경우 불필요한 갱신 요청을 생략한다. 정상 진행 폴링의 DB왕복은 기존5회에서3회로 줄었다(간헐적 heartbeat 제외).
- 추가 최적화로 활성 경기의 폴링은 인증 조건·heartbeat·잠금 획득·상태 읽기를하나의D1 트랜잭션에 묶는다. 상태를 진행하는 요청은 입력1회+커밋1회로 총2번, 다른 요청이 진행 중이면캐시 읽기1회다. SQL 단계에서 부모 방/현재 라운드/활성 참가자/고정 좌석의 일치를 검사해 비인증 요청이 잠금이나 heartbeat를 변경하지 못한다. 응답 전 기존 애플리케이션 인증도 재확인한다. 커밋은 다른 참가자의 더 최신 heartbeat를 보존한다.
- 명령 대기열의64개 상한 검사/삽입/중복 확인을한 번의 트랜잭션 왕복으로 처리한다. 꽉 찬 대기열에서도 같은 sequence재시도는 중복 없이 인정한다.
- 실제 경과 시간을정상30Hz 고정틱으로 최대1초까지 따라잡는다. 시간 배수·클라이언트 전투 판정은 사용하지 않는다. 만료 잠금이 최신 상태를 덮어쓰지 못하는 커밋 조건은 유지한다.
- 최근 실제 수신 간격에 따라100–600ms 보간 창을 정한다. 병력과 대군주에 적용하고, 동일 프레임의 명령 응답이나 오래된 리비전이 진행 중인 이동을 다시 시작하지 않게 한다. 추정 이동은 최대100ms·속도 상한을 두며2초 이상 단절 후에는 새 상태로 재기준화한다.
- 게임 애니메이션 시각·피격/반동·성큰 가시 효과·투사체의 시각적 이동을 프레임마다 갱신한다. 체력·피해·점령·승패는 서버 상태만 사용한다. 기존 스냅샷 형식과 호환되며 전투 수치는 바꾸지 않는다.

## 검증

`node --test tests/swarm-motion.test.mjs tests/swarm-d1-pacing.test.mjs tests/swarm-balance.test.mjs`17개 통과.900ms 간격에서27개의 정상틱 진행, 동시 요청에서 시간 중복 진행 방지, 대기열 상한/재시도,250ms 수신 중 이동 지속, 중복/역순 패킷, 단절 후 복원, 서버 좌표/체력 불변을 확인한다. `node scripts/swarm-audit.mjs`는 인증·세 모드·이전 라운드 차단·재접속·원본 아트/오디오 및 로컬 프로필 해시120개를 확인한다.

실제 기존 수신 기록을 동일한30Hz 시각 샘플로 재생하면, 걷는 유닛이 프레임 사이0.025월드좌표 미만 움직인 비율이 기존92.1%에서 새 렌더러49.6%로 감소했다. 이는 **DB 개선 전의1초 이상 수신 간격을 그대로 둔 렌더러 단독 비교**이며 충분한 해결을 뜻하지 않는다. 이 지표는 가짜 단조 시계를 사용한 재생의 시각 정지 비율이고 브라우저FPS/GPU 측정이 아니다. 실제 공개 배포 후 DB 경로 개선과 함께 다시 측정한다.

3회 왕복을 사용한 첫 공개 수정본은 동일한4클라이언트 실험에서 폴링 왕복 평균544ms, 상태 수신 간격 평균679ms를 기록했다. 경기 진행 속도는 기존0.301배에서1.001배로 회복됐다. 수신 간격이 남아 있어2회 왕복 트랜잭션을 추가했다. 최종 공개 측정과 브라우저 재생 결과는 배포 후 별도 검증 기록에 보관한다. 사용자가 연4647번 방의 개인 상태나 쿠키를 수집하지 않았다.

개인별200기와 기존AI/전투 엔진은 이번 변경에서 유지된다. 전체 TypeScript 검사의 기존54오류와 lint의 기존45경고는 별도로 남아 있으며, 수정 경로의 새 타입 오류는 없고 배포 빌드/관련 회귀 검사는 통과했다. 실제 휴대폰GPU·발열은 이 측정의 범위가 아니다.
