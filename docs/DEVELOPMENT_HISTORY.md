# 한판 개발 결정 및 변경 이력

기준일: 2026-08-18

이 문서는 긴 개발 스레드에서 확정된 제품 방향, 게임 규칙, UI 결정, 주요 버그 수정 요청과 남은 검증 사항을 다음 개발자가 빠르게 이어받을 수 있도록 재구성한 기록이다. 대화 순서대로 옮긴 전문이 아니며, 뒤에서 변경된 결정은 최신 결정을 기준으로 정리했다.

상세한 현재 파일 위치와 구현 상태는 `docs/PROJECT_STATE.md`, 작업 규칙은 루트 `AGENTS.md`를 함께 확인한다.

## 1. 제품의 최종 방향

### 1.1 기본 성격

- 앱 이름은 **한판**이다.
- 모바일 전용에 가깝게 설계된 술게임·파티게임 웹앱이다.
- 방장이 방을 만들고 참가자는 QR 또는 4자리 코드로 들어온다.
- 이름과 프로필을 선택한 뒤 한 방에서 여러 게임을 이어서 한다.
- 점수를 누적하는 경쟁 플랫폼보다 **한 판의 결과를 즉시 확인하고 현장에서 벌칙을 정하는 흐름**이 우선이다.
- 마이크 자동 판정, 공용 점수표, 일반적인 팀전 중심 구조는 사용하지 않는다. 참가자들이 직접 판정한다.
- 게임 선택 탭은 `개인전 / 모두 협동 / 미니(보드)게임` 구조다.
- 랜덤게임은 모든 허용 게임 중 하나를 뽑되, 게임별로 랜덤 제외 설정이 있을 수 있다.
- 게임 종료 후에는 같은 게임 다시 하기와 다른 게임 하러 가기 흐름을 제공한다.

### 1.2 모바일 UX 원칙

- 기준 화면 중 하나는 `393x664`지만 특정 높이에 고정하면 안 된다.
- 더 작거나 긴 iPhone/Android 화면에서도 캐릭터, 버튼, 전리품, 하단 장소가 잘리지 않아야 한다.
- 핵심 게임 화면은 가능하면 불필요한 페이지 스크롤 없이 한눈에 보여야 한다.
- 긴 설명이나 개인 정보는 별도 카드/팝업으로 열되, 게임 조작 영역은 작고 명확하게 유지한다.
- 길게 누르는 비밀 카드에는 텍스트 선택, 이미지 드래그, iOS 복사 메뉴가 뜨지 않게 한다.
- 비밀 역할은 `누르는 동안만 표시`가 기본이다. 다만 사라진 보석의 긴 사건 파일은 예외로 한 번 누르면 열리고 다시 누르면 닫히는 방식이다.
- 위험한 버튼은 즉시 실행하지 않는다. 나가기, 결과 보기, 게임 종료 등은 확인 단계를 둔다.
- 버튼을 누른 직후 서버 응답을 기다리며 화면이 늦게 바뀌는 느낌을 줄이기 위해 가능한 범위에서 낙관적 UI를 사용하되, 최종 판정은 서버 상태를 따른다.

## 2. 방·세션·동기화 결정

### 2.1 방과 참가

- 참가 입력창에는 과거에 입력한 방 번호가 자동으로 남지 않아야 한다.
- 브라우저 뒤로가기나 새로고침 후 오래된 방 번호가 입력창에 남는 현상을 제거하는 방향으로 수정했다.
- 대기방에서 나간 플레이어가 계속 보이던 문제를 수정 대상으로 삼았다.
- 방 번호는 게임 진행 중에도 왼쪽 상단에 항상 표시한다. 기존 한판 로고 자리보다 방 식별이 우선이다.
- 방장에게만 `대기실로 이동` 버튼을 제공하며 누르면 전원이 함께 이동한다.
- 게임 시작 전 간단한 설명 화면을 보여주고, 방장이 실제 시작 버튼을 눌러야 라운드가 시작된다.

### 2.2 나가기·재접속·방장

- 나가기는 한 번 더 확인한다.
- 진행 중 나가려는 사용자에게 게임이 진행 중이며 같은 인물로 돌아오면 계속 참여할 수 있음을 알려준다.
- 방장이 나가면 게임 중에도 다른 참가자가 방장 권한을 이어받을 수 있어야 한다.
- 장소 마피아에서는 한 명이 이탈하면 게임을 일시정지하고, 재입장을 기다리거나 방장이 전원을 대기방으로 이동할 수 있게 하는 결정을 사용한다.
- 동일 플레이어 복귀, iPhone 백그라운드 전환, 새로고침을 일반적인 흐름으로 간주한다. 세션이 끊겼다고 새 플레이어를 무조건 만들면 안 된다.
- 시크릿 창 여러 개는 브라우저 저장소나 쿠키가 공유되어 동일 사용자로 인식될 수 있으므로, 혼자 다중 사용자 테스트는 별도 브라우저 프로필 또는 디버그 봇 모드를 사용한다.

### 2.3 반응 속도

- 초기 폴링 방식의 반응 지연을 줄이기 위해 이벤트 갱신과 실시간 통신을 보강했다.
- 미로의 배달부는 Durable Object/WebSocket 구조를 사용한다.
- 다른 게임은 서버 저장 상태와 이벤트 갱신을 사용하므로 모든 클라이언트 표시가 서버 결과와 일치해야 한다.
- 약 12명 수준의 방을 염두에 두고 반응 속도를 논의했지만, 현재 각 보드게임의 공식 인원 제한은 게임별 3~8명 또는 4~8명이다. 인원 제한을 임의 확대하지 않는다.

## 3. 공통 게임 진행 UI

- 상단바에는 방 번호, 현재 게임 이름, 대기실 이동, 나가기를 배치한다.
- 상단바가 iPhone 브라우저 안전 영역이나 화면 가장자리에서 잘리지 않게 한다.
- `다 같이 도전` 같은 협동 안내는 일반 보조 문구보다 크게 표시한다.
- `우리끼리 판정하고 있어요`는 최종적으로 `진행중`으로 단순화했다.
- `누가 걸렸는지는 우리끼리 판정!`, `마이크 판정 없음`, `점수표 없음`, `팀전 없음` 같은 제품 설명용 문구는 실제 게임 화면에서 제거했다.
- 게임 결과/종료 버튼은 오조작 방지를 위해 확인 팝업을 사용하고, 확인 직후 약 1초간 중복 실행을 막는 방향을 사용했다.
- 역할 확인 카드의 글자색이 일부 브라우저에서 회색으로 변하지 않도록 명시적인 색상과 터치 상태를 사용한다.

## 4. 기본 파티게임 규칙과 변경 이력

### 4.1 라이어 계열 공통

- 오리지널, 몸으로, 얼굴로, 질문 라이어는 라이어 카드만 빨간색으로 만들지 않는다. 다른 역할 카드와 동일한 외형으로 표시한다.
- 라이어에게도 장르는 알려준다.
- `내 단어를 자연스럽게 설명하세요`는 `내 단어를 라이어가 모르게 설명하세요`로 변경했다.
- 역할 카드가 눌린 동안만 비밀 역할/단어를 보여준다.
- 길게 누르는 과정에서 아래 문구가 선택되거나 복사 메뉴가 나오는 문제가 있어 `user-select`, touch callout, drag 방지를 적용하는 방향으로 수정했다.
- 게임 다시 하기에서 라이어만 바뀌고 같은 문제가 반복되던 오류를 수정 대상으로 삼았다. 새 라운드는 이전 제시어를 피해야 한다.

#### 바보 라이어

- 바보 라이어는 본인에게 `라이어`라고 알려주면 안 된다.
- 결과에서는 `바보 라이어`와 `정답`을 별도 칸으로 보여준다.
- 다른 라이어 게임의 시작 설명에서 바보 라이어 변형 선택을 제공할 수 있지만, 바보 라이어의 정보 규칙을 일반 라이어와 섞지 않는다.

#### 몸으로/얼굴로 라이어

- 몸으로 라이어는 말 없이 몸으로 표현한다.
- 얼굴로 라이어는 얼굴/표정만 사용한다.
- 얼굴로 라이어도 역할 카드 색을 다른 참가자와 동일하게 유지한다.

#### 라이어-질문

- 과거 이름 `범인은 질문을 모른다`를 `라이어-질문`으로 변경했다.
- 게임 목록에서 얼굴로 라이어 바로 아래에 배치한다.
- 라이어만 질문을 모르거나 다른 정보를 받지만, 카드 외형은 동일하다.

### 4.2 초성 퀴즈

- 초기 3초 개인 타이머와 무작위 순서 규칙은 폐기했다.
- 최종 진행은 **술래 오른쪽 사람부터**, 틀리는 사람이 나올 때까지 순서대로 답한다.
- 방장이 `정답 공개`를 누르면 정답과 함께 `다음 문제`, `결과 보기`를 제공한다.
- 장르가 다음 문제에서 바뀌지 않던 오류를 수정 대상으로 삼았다.
- 장르 글자는 기존보다 키우되 제시어보다 확실히 작게 유지한다.
- 결과에는 해당 라운드에서 나온 문제와 정답 기록을 보여준다.

### 4.3 무한 훈민정음

- 비밀 술래와 비밀 순번은 없다.
- 게임은 초성만 던져주고 참가자들이 직접 진행하다 막히는 사람이 나오면 끝낸다.
- 안내 문구는 `마지막 술래 오른쪽으로! 제한시간 3초`를 사용했다.
- 초성 퀴즈처럼 `다음 문제` 버튼이 필요하며, 결과 보기만 있던 상태를 수정했다.

### 4.4 취향 일치

- 두 가지 선택지를 버튼으로 고른다.
- 선택한 참가자는 모두에게 `선택 완료` 상태로 보인다. 선택 내용은 결과 전까지 숨길 수 있다.
- 결과 화면에서 누가 어느 항목을 선택했는지 이름별로 보여준다.

### 4.5 중급 상식 퀴즈

- 너무 어려운 문제 대신 중급 난이도를 사용한다.
- 외부 제공 `중급_상식퀴즈_중복제거_177문제.txt`를 반영한 이력이 있으며 현재 원본은 `trivia-medium.txt`다.
- 한때 1,000문제로 확장했으나 이후 사용자가 제공한 문제집으로 교체했다. 숫자만 보고 1,000문제가 현재 요구라고 가정하지 않는다.
- 최종 진행 방식은 초성 퀴즈와 동일하다: 술래 오른쪽부터, 타이머 없음, 방장 정답 공개 후 다음 문제 또는 결과 보기.
- 장르 변경과 전체 정답 기록을 확인한다.

### 4.6 가짜 추억 찾기

- 술래에게만 1~4 입력 항목을 제공하고 문장을 쓰게 한 뒤 게임이 순서를 섞는다.
- 공통 제시어는 다른 참가자도 볼 수 있고 크게 표시한다.
- 거짓 항목만 빨간색으로 표시하지 않는다. 모든 칸 외형을 동일하게 유지한다.
- 결과 문구는 범인 이름 중심이 아니라 `가짜 추억은 n번 ~~~였습니다.` 형식이다.
- `가짜` 단어만 굵게 강조한다.

### 4.7 정확히 10초

- `화면을 보지 마세요` 대신 `정확히 10초를 맞혀보세요`를 사용한다.
- 측정 중에는 장황한 안내 대신 `진행중`을 표시한다.
- 각 참가자는 한 라운드에 한 번만 도전할 수 있다.
- 먼저 끝낸 사람부터 `이름 - 측정 시간`이 모두에게 표시된다.
- 게임 내부 다시 하기 버튼은 사용하지 않는다.

### 4.8 사진 촬영 게임

- 색깔 찾기와 초성 물건 찾기는 파일 선택보다 카메라 촬영 흐름을 우선한다.
- 촬영 직후 앱에 업로드하고, 찍힌 순서대로 사진과 이름을 세로 목록으로 표시한다.
- 사진을 누르면 확대할 수 있다.
- 일부 참가자의 업로드만 간헐적으로 실패하던 문제가 있었으므로 R2 업로드, 키 생성, 방 상태 반영, 재시도를 함께 확인한다.
- 초성 물건 찾기는 모든 한글 초성을 문제 후보로 포함한다.
- 색깔 찾기에는 별도 추가 조건을 붙이지 않는다.
- 확대 사진 퀴즈는 게임 목록에서 삭제했다.

### 4.9 아파트 게임

- 개인전 탭에 배치한다. 미니(보드)게임 탭이 아니다.
- 최소 3명이다.
- 최고층은 `인원수 + 2`층이다.
- 모든 플레이어가 1층부터 최고층 중 하나를 동시에 고른다.
- 가장 많은 사람이 겹친 층이 벌칙 대상이다.
- 같은 인원수로 겹친 층이 여러 개면 가장 낮은 층이 벌칙 대상이다.
- 혼자 선택한 층은 중복 판정에서 무시한다.
- 아무도 겹치지 않으면 가장 낮은 층의 한 명이 벌칙이다.
- 선택한 인원 수와 아직 선택하지 않은 사람의 이름을 표시한다.
- 결과는 단순 `벌칙층` 배지가 아니라 별도의 결과 화면에서 층과 해당자를 명확히 보여준다.
- UI는 사용자가 제공한 세로 아파트 참고 이미지의 단순하고 고품질인 건물 형태를 따르되, 전체 앱의 원래 어두운 배경을 유지한다.

## 5. 모두 협동 게임

### 5.1 텔레그레이션

- 1라운드: 자기 제시어를 보고 그림, 45초.
- 2라운드: 전달받은 그림을 보고 다시 그림, 40초.
- 3라운드: 전달받은 그림을 보고 다시 그림, 35초.
- 4라운드: 마지막 그림을 보고 정답 입력. 이후 결정으로 정답 입력은 시간제한을 없앴다.
- 결과에서 그림 변화 과정을 순서대로 공개한다.
- 검은색 펜 하나, 한 단계 되돌리기, 전체 지우기, 지우개, 제출을 제공한다.
- 그림 단계는 시간이 끝나면 자동 제출한다.
- 2명 이상 정답이면 통과다.
- 원래 그림을 그린 사람이 자기 그림 체인의 정답을 맞히게 배정되는 순환 오류를 수정 대상으로 삼았다. 전달 순환에서 원작자에게 돌아오지 않도록 검증한다.
- 제시어는 지나치게 어려운 네 글자 제한이 아니라 검색·검수된 중급 단어를 사용한다.

### 5.2 인물/캐릭터/줄줄이/네 글자

- 현재 플레이어 이름을 크게 표시한다.
- 제한시간은 5초다.
- 방장에게 `다음 문제`와 `실패` 버튼을 제공한다.
- 전원이 맞히면 통과한다.
- 타이머가 끝났더라도 방장이 다음 문제를 눌렀다면 해당 문제는 통과로 처리한다.
- 줄줄이 말해요만 같은 주제를 유지한다.
- 인물/캐릭터 사진은 잘못된 검색 결과가 다수 있었기 때문에 검수된 로컬 에셋을 우선하고 런타임 웹 이미지 검색에 의존하지 않는다.

### 5.3 이어말하기·팀전

- 제시어에 맞는 단어를 참가자가 한 글자씩 이어 말한다. 예: `아이돌 → 코/르/티/스`.
- 예외적으로 팀전 성격을 유지하되 앱이 점수나 팀 판정을 자동화하지 않고 참가자가 알아서 판정한다.
- 랜덤게임에서는 제외한다.
- 다음 문제 버튼을 제공한다.

### 5.4 단체 초성 퀴즈

- 두 글자 초성을 주고 인원수만큼 서로 다른 맞는 단어를 말한다.
- 3초 타이머 규칙을 사용한 이력이 있다. 다른 5초 협동게임과 혼동하지 않는다.
- 방장만 다음 문제로 넘긴다.
- 다음 문제를 무한 생성하거나 종료 조건을 잃는 오류가 있었으므로 문제 수/결과 전환을 회귀 테스트한다.

## 6. 깜짝 룰

### 6.1 주기와 표시

- 대기방에서 방장이 깜짝 룰을 켜고 끌 수 있다.
- 방 입장 직후 바로 뜨지 않는다. 최초 5분 후 등장한다.
- 한 규칙은 10분 동안 진행되고, 10분 휴식 후 새로운 규칙이 시작된다.
- 규칙 등장 시 알림음과 진동을 사용한다. 브라우저 권한/사용자 상호작용 제한에 따라 실패해도 게임은 진행되어야 한다.
- 처음부터 오른쪽 사이드에 표시한다. 과거의 화면 중앙 등장 후 사용자가 옮기게 하는 방식은 폐기했다.
- 팝업은 접고 펼 수 있으며 X 버튼을 사용하지 않는다.
- 접으면 남은 시간만 보인다.
- 화면 좌우 어느 쪽에 있어도 세로로 이동 가능하게 했던 이력이 있으나, 최신 기본 위치는 오른쪽이다.
- 타이머가 끝나면 사라진다.
- 게임 화면과 대기방에서도 같은 방의 사용자들이 공통 주기 상태를 공유해야 한다.

### 6.2 규칙별 결정

- 동물의 왕국: 각 사용자에게 서로 다른 동물 미션을 주고 말하기 전 울음소리를 내게 한다.
- 비밀미션: 모두에게 팝업을 띄우고 각자 다른 미션을 준다. 종료 후 전체 미션을 공개한다.
- 모션게임: 모두에게 시작 팝업을 띄운다. 한 명에게만 `술래! 다른 사람이 따라 하게 행동하세요`, 나머지에게 `눈치보고 술래의 행동을 따라하세요`를 준다.
- 금지어 게임: 기존 구현 유지.
- 웃음 참기: 기존 구현 유지.
- 용용체: 말끝을 `~용` 형태로 사용한다.
- 이응 게임: 받침을 이응 중심 규칙으로 바꿔 말한다.
- TWO TOUCH: 모든 물건을 두 번 내려놓는다.

## 7. 사라진 보석

### 7.1 핵심 방향

- 4~8명 추리 보드게임이다.
- 게임 설명에서 특수 역할 사용 여부를 선택하며 4인 이상에서만 활성화한다.
- 사건 장소, 도난품, 도구, 시간대, 범인 특징, 알리바이, 질문 카드, 사건 배경을 조합한다.
- 알리바이는 최종적으로 50종으로 확장했고, 비슷하거나 중복된 문장을 피하며 실제로 말할 법한 내용으로 구성했다.
- 범인은 자신의 가짜 알리바이를 다른 플레이어에게 자연스럽게 직접 말한다.

### 7.2 논리 설계

- `사건 장소가 서재`인데 범인 알리바이가 `서재에서 책을 찾았다`처럼 범인을 즉시 특정하는 모순을 만들지 않는다.
- 사건 장소와 알리바이의 표현을 직접 일치시키지 않고, 장소별 금지 조합을 적용한다.
- 특징 단서와 플레이어 프로필 행동이 사실상 같은 문장인 조합을 피한다.
- `범인은 누구 중 한 명입니다`처럼 인원을 곧바로 좁히는 노골적인 단서는 피한다.
- 모든 단서를 합쳐도 범인이 단독 확정되지 않고 최종 용의자 2명이 남아야 한다.
- 각 플레이어가 단서를 여러 개 공개하는 방식이 아니라 **룰상 한 사람당 단서 하나만 말할 수 있게** 변경했다.
- 난이도 차이는 정보량과 표현의 직접성으로 조정하되, 논리적으로 해결 불가능하거나 한 줄로 정답이 드러나면 안 된다.
- `10시 10분 전후 행동을 먼저 말하지 마세요`처럼 플레이어가 기준 시간을 알 수 없어 수행 불가능한 지시는 제거하거나 실제 사건 시각을 기준으로 이해 가능한 문장으로 바꾼다.
- 범인/특수 역할 이탈 처리는 별도 예외로 남겨두고, 그 외 논리 오류는 감사 스크립트 대상이다.

### 7.3 UI·이미지

- 초기 이모티콘 카드와 소수의 공용 이미지는 품질 목표에 미달했다.
- 사건 배경은 세로로 긴 고품질 이미지로 보여주고, 그 위에 도난품·장소·시각·도구 정보를 오버레이한다.
- 사건 파일도 글씨를 이미지 위에 얹는 형태로 통일한다.
- 단순 7개 완성 이미지 조합보다 장소, 배경, 아이템, 시계, 도구 등 재사용 가능한 에셋 조합을 대량 제작하는 방향을 채택했다.
- 사건 파일이 너무 길어 화면에 다 안 보이던 문제 때문에 이 게임에 한해 버튼으로 열고 다시 눌러 닫는 상세 화면을 사용한다.
- 핵심 규칙과 사건 설명 문장을 짧고 일목요연하게 다듬었다.

### 7.4 알려진 후속 확인

- 4~8명 모든 조합에서 항상 정확히 2명의 후보가 남는지 `test:gem-logic`으로 계속 확인한다.
- 새 알리바이/특징/단서를 추가할 때 장소 금지 조합과 의미 중복을 같이 검사한다.
- 사건 이미지 수가 많으므로 사용되지 않는 에셋을 임의 삭제하지 않는다.

## 8. 장소 마피아

### 8.1 확정된 맵과 이동

인접 관계는 아래와 같다.

```text
주택가 ─ 경찰서
  │       │
 광장  ─ 공원
  │       │
 골목  ─ 병원
```

- 자기 위치와 위 연결선으로 직접 이어진 장소만 이동 가능하다.
- 예를 들어 주택가에서 골목으로 바로 갈 수 없다.
- 이동 가능 장소와 마피아 습격 가능 장소가 같은 인접 그래프를 정확히 사용해야 한다.
- 경찰서, 광장, 병원은 연속 체류가 금지된 특수 장소다.
- 현재 위치 마커는 건물 중앙에 크고 명확하게 표시한다.

### 8.2 밤 진행

- 밤은 항상 20초 고정이며 전원이 빨리 결정해도 조기 종료하지 않는다.
- 시민은 이동 확정 후 대기한다.
- 살인 담당 마피아만 이동 확정 후 최종 위치에서 공격 가능한 인접 장소 한 곳을 고른다.
- 마피아가 공격 장소를 고를 때 다른 플레이어 위치는 보여주지 않는다.
- 같은 장소에서 누구를 만났는지는 밤 종료 후 개인에게 공개한다.
- 20초 종료 시 서버가 이동 → 살인 → 병원/광장/경찰서 효과를 한 번에 판정한다.
- 마피아가 공격을 고르지 않으면 살인은 실패한다.
- 공격 미선택, 빈 장소 공격, 병원 방어 성공은 모두 `어젯밤은 조용한 밤이었습니다. 아무도 죽지 않았습니다.`로 통일한다.
- 습격이 실제 발생했으면 밤→낮에 총성, 실패했으면 새 지저귀는 소리를 사용한다.
- 이동 불가 장소는 어둡고 창문 소등, 이동 가능은 일부 창문 점등, 선택된 장소는 전체 점등·확대·황금 테두리, 공격 선택은 붉은 창문과 붉은 외곽광을 사용한다.

### 8.3 낮·투표

- 일반 마피아 규칙 설명은 줄이고 이 게임만의 이동/특수 장소/인접 공격만 설명한다.
- 투표는 익명이다.
- 재투표는 없다. 동률이면 처형 없이 다음 밤으로 간다.
- 투표시간은 50초다.
- 모든 참가자에게 `투표시간 10초 단축` 버튼을 제공한다. 각 사용자는 한 번만 반영되는 토론 단축과 같은 방식을 사용한다.
- 투표 대상을 누르면 텍스트 선택과 강조 색이 동시에 즉시 바뀌어야 한다. 서버 반영 전 빨간 선택 칸이 늦는 현상을 피한다.
- 사망자에게는 화면을 어둡게 하고 사망 상태를 명확히 표시한다.

### 8.4 역할과 인원

- 4~8명이다.
- 게임 설명에서 마피아 1명 또는 2명을 선택할 수 있다.
- 역할 확인 소리는 시민과 마피아가 같아야 한다. 소리로 역할을 추측할 수 없어야 한다.
- 역할 카드는 누르는 동안만 보이고 복사/드래그를 방지한다.
- 한 명 이탈 시 게임을 멈추고 재접속 또는 대기방 이동을 선택한다.
- 마피아 디버그 모드는 최종적으로 삭제했다.

### 8.5 UI 아트 방향

- 사실적인 도로 위에 픽셀 건물 PNG를 올리는 혼합 스타일은 폐기했다.
- 전체를 하나의 아이소메트릭 픽셀아트 도시처럼 보여야 한다.
- 카메라는 지면 기준 약 70도, 거의 직교 투영, 모든 건물 동일 회전, 지붕 60%/창문 면 40% 정도다.
- 6개 장소는 각 구획 안에서 건물, 부지, 인도, 진입로, 녹지, 접지 그림자까지 완결된다.
- 도로, 골목, 교차로, 횡단보도, 주차장, 담장, 화단, 가로등은 건물과 같은 픽셀 밀도와 색감이어야 한다.
- `BUS`, `TAXI` 같은 글자 장식으로 도시감을 대신하지 않는다.
- 장소명은 건물 밑 긴 검은 바 대신 부지 안의 작은 고급 명패로 통합한다.
- 화면 상단 12~18%는 같은 픽셀 화풍의 하늘, 구름/해/달, 먼 도시 실루엣으로 맵과 이어진다.
- 과한 `도시가 잠듭니다/깨어납니다` 전체화면 전환은 삭제했다. 낮/밤은 하늘색, 조명, 창문, 색온도만 짧게 바꾼다.
- 하단 골목/병원이 브라우저 툴바나 선택 패널에 가려지지 않게 안전 영역과 맵 높이를 계산한다.
- 준비 화면은 실제 인게임 맵 이미지를 사용하고, 케이스 룰 페이지는 삭제했다.
- 연출 설정 칸은 삭제했다.
- 게임 설명은 인게임 미니 사진 없이 핵심 특수 규칙만 짧게 보여준다.

### 8.6 회귀 위험

- 과거 주택가→골목 같은 비인접 이동이 허용된 오류가 있었다.
- 경찰서/병원/광장 연속 체류가 허용된 오류가 있었다.
- 토론 10초 단축 알림 팝업이 사라지지 않은 문제가 있었다.
- 하단 장소가 작은 모바일 화면에서 가려진 적이 있다.
- 위 항목은 `test:place-mafia`와 실제 모바일 흐름에서 반드시 재검증한다.

## 9. CASH AND GUNS

### 9.1 기본 규칙과 표현

- 제목은 영문 **CASH AND GUNS**다.
- 4~8명, 8라운드, Power Mode는 사용하지 않는다.
- `GODFATHER` 표기는 한국어 `대부`로 변경한다.
- 픽셀아트 캐릭터, 배경, 테이블, 전리품, 버튼과 프레임을 하나의 어두운 마피아/산업풍 화풍으로 통일한다.
- 원형 테이블 배치에서 좌우뿐 아니라 반대편 캐릭터 방향과 총 방향을 고려한 에셋을 사용한다.

### 9.2 조준과 대부

- 플레이어 선택 팝업을 없애고 테이블 주변의 실제 캐릭터를 직접 터치한다.
- 선택 캐릭터에는 픽셀 타깃/테두리를 명확히 표시한다.
- 방향 점선은 내 조준만 보이며 캐릭터 중앙끼리 연결하되 여러 화살표가 한 점에 겹쳐 보이지 않게 중간 경로/오프셋을 사용한다.
- 모바일에서 화살표가 비정상적으로 커지지 않도록 SVG/좌표를 뷰포트에 맞춰 계산한다.
- 하단 확인 버튼으로 확정한다.
- 시간초과 시 마지막으로 선택한 플레이어를 조준 대상으로 확정한다.
- 대부 권한은 모든 플레이어의 조준이 확정된 뒤에만 팝업/단계가 시작된다.
- 대부는 목표를 한 번 바꾸거나 사용하지 않을 수 있다. 시간초과 시 사용 안 함이다.

### 9.3 결단·총격

- 결단 단계는 시간제한이 없다.
- 각 플레이어 이름 아래 `결정중` 또는 `결정완료`를 작게 표시한다. 별도 대형 결정 카드로 화면을 가리지 않는다.
- 숙인다/버틴다 버튼과 총격 결과에는 명확한 버튼음·총성·피격 효과음·애니메이션이 필요하다.
- 오디오가 브라우저 자동재생 정책에 막힐 수 있으므로 첫 사용자 입력 후 AudioContext를 활성화한다.
- 효과음은 역할이나 탄환 정보를 의도치 않게 먼저 누설하면 안 된다.

### 9.4 전리품 예약 드래프트

- 원작의 한 사람씩 기다리는 선택은 온라인에서 느리므로 **실시간 예약 드래프트**를 사용한다.
- 실제 획득 순서는 대부 기준 시계방향을 유지한다.
- 모든 생존 플레이어가 자기 차례 전에도 원하는 전리품 우선순위를 예약한다.
- 자기 차례 전까지 우선순위를 자유롭게 변경할 수 있다.
- 앞사람이 아이템을 가져가면 그 항목은 즉시 제외되고 다음 우선순위가 올라온다.
- 자기 차례가 되면 현재 1순위를 즉시 획득한다.
- 선택이 없으면 짧은 제한시간 뒤 자동 선택한다.
- 예약 초기화 버튼을 제공한다.
- 각 전리품 옆에는 예약 순위를 작게 표시한다.
- 예약 변경은 즉시 화면에 반영되어야 하며 늦게 취소되거나 과거 응답이 최신 선택을 덮지 않아야 한다.
- 전리품은 별도 큰 박스를 반복하지 않고 `아이템 이미지 - 이름(금액) - 예약순위`로 간결하게 보여준다.
- 글자는 읽기 좋게 키우고 장황한 부가설명은 없앤다.
- 전리품 목록이 화면 밖으로 나가지 않게 테이블 내부 가용 높이와 아이템 수에 맞춰 압축한다.

### 9.5 자산과 보너스

- `내 돈`/`내 전리품 보기`는 처음 보는 사용자도 누를 수 있는 버튼임을 알 수 있게 박스와 상호작용 표시를 사용한다.
- 팝업에서 현금, 다이아, 그림 컬렉션, 총가치를 보여준다.
- 다이아 단독 1위 보너스와 그림 컬렉션 세트 보너스를 작게 설명한다.
- 대부 토큰이 빈 박스나 깨진 문자로 나오지 않게 실제 픽셀 에셋과 대체 텍스트를 확인한다.

### 9.6 반응형·에셋

- 과거 `393x664` 고정 캔버스로 인해 작은 화면에서는 캐릭터가 테이블을 침범하고 큰 화면은 검게 남는 문제가 있었다.
- 게임 영역은 화면 비율에 맞춰 전체가 함께 스케일되어야 하며 캐릭터의 테이블 상대 좌표를 유지한다.
- 캐릭터는 어떤 행동/방향에서도 잘리거나 플레이어 이름을 가리지 않아야 한다.
- 디버그 버튼은 전리품 취소/예약 초기화 버튼과 겹치지 않게 별도 안전 위치에 둔다.
- `내 전리품 보기`는 명확한 박스 버튼으로 표현한다.

### 9.7 오디오

- 총격, 피격, 버튼 등의 효과음을 전체 단계에서 확인해야 한다.
- 사용자가 제공한 `BGM.mp3`를 `public/cash-n-guns/audio/bgm.mp3`에 반복 재생 BGM으로 사용한다.
- BGM은 긴장감 있는 마피아 분위기이며 반복 재생한다.
- 공개 GitHub에 올리기 전 사용자가 해당 BGM 배포 권리를 확인해야 한다.

### 9.8 디버그 모드와 현재 검증 상태

- 게임 설명 화면에서 디버그 모드를 켜고 끌 수 있어야 한다.
- 혼자서 시작하면 부족한 자리를 봇이 채워 전체 라운드를 시험할 수 있어야 한다. 단순 토글만 보이고 시작 조건이 4명으로 막히면 안 된다.
- 최신 작업 요청에서는 Sites 배포와 실제 브라우저 디버깅을 하지 말고 파일만 저장하라고 명시했다.
- 따라서 마지막 전리품 반응성, 화살표, 모바일 크기, BGM/효과음 변경은 **구현 여부를 코드로 확인하고 실제 플레이를 다시 검증해야 하는 상태**다.

## 10. 수상한 딜러들·미로의 배달부

### 10.1 수상한 딜러들

- 3~8명 비공개 경매 게임이다.
- 소장품 카드, 아이템, 조항을 사용한다.
- 2D 카드, 3D 스타일, 실사 스타일 등 여러 제작 에셋이 남아 있다. 현재 런타임 참조와 제작 후보를 구분하되 삭제하지 않는다.
- Cloudflare 무료 사용량을 논의했지만 최종 판수는 요청량, R2/D1/Worker 호출에 따라 달라진다. 문서에 고정 판수를 하드코딩하지 않는다.

### 10.2 미로의 배달부

- 최대 8명, 3D 미로와 서버 판정 이동을 사용한다.
- WebSocket/Durable Object 실시간 통신을 사용한다.
- 별도 프로토타입과 운영 앱 통합본이 모두 존재하며, 프로토타입은 `archive/maze-map-prototype/`에 보존했다.
- 별도 원본 저장소에는 commit history가 없었으므로 소스만 보존했다.

## 11. 콘텐츠·사진·저작권 결정

- 음악 퀴즈는 저작권 위험 때문에 기본 게임 목록에서 제거했다.
- 인물/캐릭터/확대 사진은 런타임마다 웹 검색해 즉석에서 가져오지 않는다. 검색 결과 오류, CORS, 링크 만료, 엉뚱한 이미지, 저작권 문제가 발생할 수 있기 때문이다.
- 검수된 로컬 파일과 고정된 데이터 매핑을 사용한다.
- 인물 사진은 한 차례 전체 검수 완료로 간주했지만, 캐릭터 사진은 피터팬, 팅커벨, 티몬, 품바, 셜록 홈즈, 피노키오, 뽀로로, 헬로키티, 토토로, 곰돌이 푸, 피글렛, 소닉, 스폰지밥, 뽀빠이, 도로시, 프랑켄슈타인, 앨리스, 티거, 타요, 둘리, 빨간머리 앤 등을 반복 재검수한 이력이 있다.
- 새 캐릭터를 추가할 때 이름만 맞는 상품 사진, 팬아트, 다른 인물 사진을 사용하지 않는다.
- `content-catalog.html`은 검수/관리 화면이고, 실제 런타임 데이터는 동기화된 `content-data.js` 계열을 사용한다.
- 상식·제시어 대량 데이터는 중복과 난이도, 부적절한 문장을 검사한다.

## 12. 주요 버그 수정 이력 요약

다음은 과거에 실제로 문제로 확인되어 수정 대상으로 다뤄진 항목이다. 현재도 회귀 가능성이 높은 체크리스트다.

### 방/공통

- 나간 사용자가 대기방에 남음
- 참가 입력에 이전 방 번호가 남음
- 새로고침/뒤로가기에서 오래된 사용자나 방 번호 복원
- 방장 이탈 후 권한 위임 실패
- 결과/나가기 버튼 중복 또는 오조작
- iPhone 역할 카드 길게 누르기에서 텍스트 선택/복사 메뉴
- 방별 깜짝 룰 타이머가 사용자마다 다르게 시작
- 첫 입장 즉시 깜짝 룰 노출

### 기본 게임

- 다시 하기에서 같은 제시어 반복
- 바보 라이어에게 본인이 라이어라고 노출
- 사진 업로드가 일부 사용자에게만 간헐 실패
- 텔레그레이션 원작자가 자기 체인을 맞힘
- 단체 초성 다음 문제가 무한 생성
- 협동 타이머가 의도와 다르게 8초로 표시
- 초성/상식 장르가 다음 문제에서 바뀌지 않음
- 정확히 10초 중복 참여

### 사라진 보석

- 사건 장소와 범인 알리바이가 직접 일치해 범인이 즉시 특정됨
- 특징 단서가 프로필 행동과 사실상 동일
- 단서가 너무 쉽거나 반대로 의미 없는 수준으로 어려움
- 사건 파일이 화면보다 길어 잘림
- 사건 카드 이미지 수가 적고 이모티콘 중심이라 몰입도 저하
- 플레이어가 알 수 없는 절대 시각 기준 지시

### 장소 마피아

- 인접하지 않은 장소로 이동/공격 가능
- 특수 장소 연속 체류 가능
- 하단 장소가 모바일 브라우저 UI에 가림
- 토론시간 단축 알림이 사라지지 않음
- 익명투표 선택 글자와 강조색의 반영 시점 불일치
- 역할 카드 마피아만 다른 소리가 남
- 사망자 화면 상태가 불명확

### CASH AND GUNS

- 전리품이 화면 밖으로 나감
- 예약이 늦거나 취소되고 오래된 응답이 다시 반영됨
- 결정중 UI가 너무 큼
- 모바일 화살표가 비정상적으로 커지거나 방향을 읽기 어려움
- 총성/효과음이 재생되지 않음
- 캐릭터와 이름표가 겹치거나 화면 크기에 따라 테이블 침범
- 큰 화면에서 남는 영역이 검게 보임
- 전리품에 금액 정보가 없거나 박스가 과도함
- 대부 토큰이 깨진 박스로 보임
- 대부 권한이 조준 완료 전에 열림
- 디버그 토글을 켜도 혼자 시작할 수 없음

## 12-1. 오리지널 마피아 추가 (2026-08-19)

- 개인전 목록에 `오리지널 마피아`를 추가했다. 서버 규칙은 `app/api/_lib/mafia.ts`, 화면은 `app/mafia.tsx`와 `app/mafia.css`에 있다.
- 4~8명, 마피아 1~2명, 경찰 1명, 의사 1명을 배정한다. 역할 확인은 길게 누르는 동안만 표시한다.
- 밤은 20초 고정이며 시민·경찰·의사·마피아 모두 같은 밤 화면에서 이동/행동을 확정한다. 마피아가 공격 대상을 제출하지 않으면 공격하지 않는다.
- 의사는 같은 사람을 연속 보호할 수 있다. 경찰 수사 결과는 경찰에게만 보인다. 밤 종료 전 다른 플레이어 위치나 살인 선택은 공개하지 않는다.

- 처형 결과에서 역할은 공개하지 않으며, 게임 종료 시에만 최종 역할을 공개한다.
- 역할 확인 제한시간을 없애고 전원이 확인 완료를 누르면 밤으로 이동한다. 낮/밤 픽셀 배경, BGM, 클릭·단계 전환 효과음을 연결했다.
- 토론과 익명 투표는 생존자마다 한 번씩 10초 단축할 수 있다. 처형 후보는 20초 최후의 변론 뒤 생사 투표를 거친다.
- 낮/밤 BGM은 OpenGameArt의 CC0 트랙으로 교체했고, 총격음은 Wikimedia Commons 공개 도메인 효과음을 사용한다. 실제 피해자가 확정된 `day_reveal`에서만 총격음이 재생되며, 조용한 밤·공격 미선택·의사 방어 성공에는 재생하지 않는다.

## 13. 배포·저장소 이력

- 앱은 OpenAI Sites 계열 배포를 사용해 왔으며 기존 Git 원격은 `git.chatgpt-team.site`다.
- 과거 Sites 재배포 과정에서 Git Credential Manager 로그인 창이 나타난 적이 있다. 해당 창은 Sites 내부 Git 원격 인증이며 사용자가 모르는 임의 자격 증명을 입력하면 안 된다.
- 다른 계정 환경에서 작업할 때는 `수정·저장만 하고 Sites에 배포하지 말라`는 요청이 있었고, 마지막 CASH AND GUNS 변경이 그 상태다.
- 현재 전체 백업 작업에서는 기존 history를 유지하고 GitHub 저장소를 별도 원격으로 추가할 예정이다.
- 기존 `origin`을 GitHub 주소로 덮어쓰지 않는다.
- 현재 백업 commit 예정 메시지는 `Backup complete 술게임 project`이며, 사용자 확인 전 commit/push하지 않는다.

- 기존 어두운 서부 장터 UI를 폐기하고 `docs/FRONTIER_BEANS_UI_V3_SPEC.md`를 새 화면의 고정 기준으로 삼았다. 5인 화면은 방/단계/설명/옵션, 상대 4명, 중앙 더미·공개콩, 내 농부·밭, 손패만 남긴다.
- `public/frontier-beans/ui-v3/`에 밝은 농장 배경, 양피지 손패 카드 8종, 열매 부착점이 있는 콩나무를 로컬 고정 에셋으로 저장했다. 카드 이름과 구성 수는 강낭콩 6, 팥 8, 동부 10, 대두 12, 완두콩 14, 똥콩 16, 칠리콩 18, 푸르대콩 20이다.

- 거래 화면은 상대와 나에게 각각 8칸을 제공하고 같은 콩은 한 카드의 `×n개`로 묶는다. 카드 없이 대가를 요구하는 거래는 막되, 대가를 요구하지 않는 공짜 증여는 허용한다.
- 150ms 길게 누르기 드래그와 카드 탭→밭 탭을 함께 구현했다. 손패 순서는 바꾸지 않고 서버 성공 전 카드를 제거하지 않으며, 합법 밭 금빛/불법 밭 어둡게, 드래그 고스트, 가장자리 자동 스크롤, 진동과 심기 애니메이션을 적용했다.
- 393×664, 360×640, 430×932에서 문서 오버플로가 없고 화면 스크롤 없이 모든 핵심 영역이 들어오는 것을 확인했다. 실제 5인 방에서 첫 카드 심기, 거래 진입, 카드 선택, 콩 선택기, 무료 증여를 서버 응답까지 검증했다.
- 생성 원본의 비율과 투명도를 유지해 실제 표시 크기에 맞게 에셋을 최적화했다. UI V3 PNG 묶음은 약 16.2MB에서 5.7MB로 줄어 모바일 초기 다운로드와 이미지 메모리 부담을 낮췄다.
- 모바일 드래그가 시작되기 전에 10px 이동만으로 제스처를 취소하던 문제를 수정했다. 포인터 이동·해제를 카드 요소가 아닌 브라우저 창에서 추적하고, 위쪽/대각선 이동은 즉시 드래그로 전환하며 손패의 거의 수평인 이동만 좌우 스크롤로 구분한다. 실제 393×664 화면에서 손패→거래판, 거래판→손패 취소, 받은 콩→밭의 세 경로를 검증했다.

### 실시간 양자 거래·명시적 수확 흐름 (2026-08-20)

- 거래 제안/반대 제안 목록을 없애고 현재 턴 농부가 상대를 눌러 여는 1:1 실시간 거래방으로 교체했다. 거래방은 두 참가자 화면에 동시에 표시되며 각자의 선택 카드가 서버 상태로 공유된다.
- 거래 시작자와 상대가 각각 `거래하기`를 눌러야 카드가 이동한다. 한쪽이 먼저 확인하면 상대 화면에 확인 상태를 표시하고, 어느 쪽이든 `거래 취소`로 방을 닫을 수 있다. 최종 카드 소유권과 양쪽 확인 여부는 서버 엔진에서 재검증한다.
- 거래창을 HUD까지 덮는 상단형 보드로 확장하고 카드·빈 슬롯을 키웠다. 손패 카드의 덱 구성 수 표기는 제거하고 이름을 카드 하단 내부에 크게 배치했다.
- 손패 카드를 누르면 같은 자리에서 수확표 뒷면으로 전환한다. 150ms 드래그와 거래 선택 탭 방식은 그대로 병행한다.
- 밭을 누른 경우에만 `수확하기`가 나타난다. 다른 종류의 콩을 놓아도 더 이상 자동 수확하지 않으며 서버와 UI 모두 `밭을 먼저 수확한 뒤 심어 주세요`라고 안내한다. BOT 역시 같은 규칙 아래에서 수확과 심기를 별도 행동으로 수행한다.
- 실제 393×664 방에서 카드 뒤집기, 거래창 위치, 거래 카드 선택, BOT 즉시 성사 후 창 닫힘, 다른 콩 심기 거부와 수확 버튼 노출을 확인했다. 실시간 양쪽 확인 및 카드 교환은 서버 감사 테스트로 검증했다.

### 받은 콩 단계·콩 그림·손패 탐색 보정 (2026-08-20)

- 받은 콩 심기 단계에도 내 밭과 기존 손패의 투명도·채도가 바뀌지 않도록 잠금 스타일을 수정했다. 기존 손패는 순서와 조작만 잠기고 원래 색으로 계속 보인다.
- 가장자리에 옆 콩 스프라이트가 섞여 있던 구형 PNG를 교체했다. `public/frontier-beans/bean-{azure,copper,roast,forest,honey,midnight,ruby,ivory}.png`에 8종을 각각 독립된 투명 픽셀아트 식물 스프라이트로 저장하고, 상대 미니 밭·밭 표시·게임 설명은 이 식물 에셋을 사용한다. V3 카드는 손패 카드 전용으로만 유지한다.
- 1장 밭 보호는 밭을 누른 뒤 버튼으로 바뀌는 방식이 아니라 해당 밭 하단에 항상 표시한다. 수확 가능한 밭만 눌렀을 때 `수확하기`가 나타난다.
- 손패의 보이지 않는 카드가 오른쪽에 있으면 `>>`, 왼쪽에 있으면 `<<`를 표시한다. 화살표를 누르면 해당 방향으로 이동하며 직접 스크롤한 뒤에도 양쪽 상태가 즉시 갱신된다.
