# 군단 땅따먹기 연동

한판의 미니(보드)게임 목록과 기존 방의 참가자/HttpOnly 세션 쿠키를 사용한다. 별도 방 코드를 입력하지 않고 같은 라운드의 모든 참가자를 고정된 좌석에 연결한다. 2명은1대1,4명은2대2/개인전이며, AI 연습은 별도로 제공한다. 엔진·규칙·아트·오디오·터치 조작은 군단 원본을 복사하고 배경·문자 색과 호스트 이동 경계만 적용한다.

2026-11-02 개인별200기 요청 이후, 아래 모바일 밸런스는 한판에서 별도로 관리한다. 원작 `RULES`는 보존하며 `MOBILE_RULES`와 AI 판단, 병력 표시에 한판 전용 변경이 있다. 그래픽·오디오·맵·터치 조작은 유지한다.

## 개인별200기 모바일 프로필

- 1대1·팀전·개인전·AI 연습 모두 각 플레이어의 살아 있는 히드라 최대200기. 성큰과 대군주는 제외한다. 팀원이나 탈락자의 여유 한도를 빌릴 수 없다. 1대1은최대400기,4인은최대800기다.
- 한도 도달 시 해당 소유자의 증원만 멈추고, 손실 후 다음 정상 생산 판정에서 재개한다. 시작1000·점령250·1.302초 증원·구역80기·강화50·기존 전투 수치를 유지한다. 거점이 많으면 손실 후 충원이 빠르고 여러 전선에 증원할 수 있다.
- 이미 진행 중인 구버전 전투의200기 초과 생존 병력을 삭제하지 않는다. 추가 생산은200기 미만으로 내려간 뒤 재개한다. 새 경기에서는 항상200기 상한을 검증한다.
- AI는 거점을 실제 사격할 수 있는 근접 위협에 대응하며 위협 유닛을 요격한다. 먼 적 때문에 자신의 거점 중앙으로 후퇴하는 판단을 제거한다.8초간 군단 중심 이동/처치/실제 교전이 모두 없으면10초 공격 우선 창을 열어 목표를 다시 고른다. AI 수치·자원 보너스는 없다.
- 서버와 AI 연습이 같은 엔진을 사용한다. 개인 한도와 AI 진행 상태는 체크포인트 복원 후에도 유지한다. 클라이언트의 병력 수나 승리 주장은 사용하지 않는다.
- HUD는 모든 좌석에 현재/200을 표시하고, 규칙 카드에 한도·손실 시 증원·성큰/대군주 제외를 설명한다. 작은 화면에서 병력 표시가 필요하면 줄바꿈한다.
- `public/swarm/source.json`의 기존 `hashes`는 원본 해시, `localHashes`는 한판 수정 파일 해시다. `localProfile`이 있으면 원본 복사 스크립트는 덮어쓰기를 중단한다. 원본 업데이트는 이 프로필의 변경을 병합한 뒤 기록한다. 원본 군단 사이트에는 이 패치를 배포하지 않는다.
- 빠른 검증: `node --test tests/swarm-balance.test.mjs`, `node scripts/swarm-audit.mjs`. 경기 시간: `node scripts/swarm-balance-bench.mjs --hp=8000 --output=tmp/swarm-200-hp8000.json`. 후자는 실제30Hz AI 경기이며 시간제 강제 승패가 없다.

## 영향 범위

- `.openai/hosting.json`, Worker 바인딩과 기존 D1/R2/DO 설정은 변경하지 않는다. 한판의 기존 `DB`에 `swarm_rooms`, `swarm_states`, `swarm_commands` 세 테이블을 추가하는 새 Drizzle 마이그레이션을 생성한다. 기존 마이그레이션과 방 테이블은 보존한다.
- 공용 방에는 모드/라운드 식별자/참가자 ID만 저장한다. 전투 체크포인트와 RNG는 별도 군단 테이블에 저장하여 공용 방 폴링이 전체 병력을 전송하지 않게 한다.
- 매 게임 요청은 한판 세션으로 참가자를 인증하고 현재 방·게임·라운드를 확인한다. body의 좌석/플레이어/토큰은 권한으로 사용하지 않는다. 군단 좌석 토큰은 세션 해시와 라운드에서 서버가 유도하며 공개 응답에 넣지 않는다.
- 판정은 기존 서버 엔진과 D1 잠금/트랜잭션을 사용한다. 현재 라운드의 승패를 클라이언트 결과 메시지로 확정하지 않는다.
- 명시적 이탈은 참가자와 쿠키를 보존하고 상태를 대기 중으로 바꿔 재접속을 허용한다. 방장이 이탈하면 공용 방장을 다른 활성 참가자에게 위임한다. 다른 참가자의 전투는 계속된다. 새로운 참가자는 진행 중인 전투에 끼어들지 못한다.
- 게임 시작/종료/대기실 이동은 기존 한판 호스트 권한과 확인 UI를 사용한다. 깜짝 룰과 다른 게임의 비밀 상태/판정은 바꾸지 않는다.

## 원본과 갱신

`node scripts/sync-swarm.mjs ../swarm-territory`가 복사 대상을 명시한다. `public/swarm/source.json`에 원본 커밋과 파일 해시를 기록한다. 호스팅 ID·자격증명·기존 서버 데이터는 복사하지 않는다. 원본 군단 사이트는 수정하지 않는다.

색상은 `public/swarm/hanpan-theme.css`에 분리한다. 부모 프레임은 세로 UI를 유지하고 iframe은 자체 viewport/safe-area/최소 전장·스크롤 규칙을 사용한다. 가로 전용 UI나 회전 안내/일시정지를 추가하지 않는다. 최소320px 폭과 작은/긴 화면에서 조작부·팝업을 검증한다.

## 검증

- `node scripts/swarm-audit.mjs`: 인증·동시 참가·세 모드·중복 명령·이전 라운드 차단·방장 위임·재접속·원본 파일 해시112항목 통과.
- 한판 브라우저에서1대1/4인 팀전, AI 연습, 상대 강화 표시, 나가기 취소 후 연결 유지 확인.
- 화면320×568,360×640,393×664,390×844,430×932,768×1024에서4인 전투의 가로 넘침 없음. 모든 주요 버튼48px, 조작부가 화면 안에 들어옴. AI 연습은 외부 돌아가기 바가 있어320×568에서21px 내부 세로 스크롤을 허용함. 규칙 팝업은 화면 안에서 스크롤함. 화면 크기 에뮬레이션이며 실물 GPU·발열·회선 측정은 아님.
- 기존 전체 렌더 검사6개 중5개 통과. 기존 텔레그레이션의 없어진 제한시간 코드 패턴을 기대하는1건이 실패하며, 수정 전 커밋에서도 해당 패턴이 없음을 확인함. 이 작업에서 다른 게임 규칙을 바꾸지 않음.
- 전체 TypeScript 검사에는 기존 미로·콩시장 및 Cloudflare 전역 타입 설정 오류가 남아 있음. 군단 신규 파일 오류는 정리했으며 배포 빌드와 lint를 별도로 검증함. lint의 기존/원본 미사용 변수 경고는 원본 엔진 보존을 위해 유지함.
