# 군단 화면 반응 개선 — 2026-11-04

서버 교체 후에도 조작 반응과 화면 끊김이 남는다는 보고로, 전송 시간과 그리기 비용을 분리했다. 공개 네 참가자 방의 재측정은 상대 상태 반영 평균58ms/p9568ms였다. 이 값은 휴대폰의 그리기 시간을 포함하지 않는다.

## 수정

- 128×144 원본 스프라이트를 매 병력·매 프레임 축소하고 좌우 변환하던 경로를, 실제 캔버스 해상도에 맞춘 양방향 이미지 캐시로 바꿨다. 프레임마다 save/translate/scale/restore를 반복하지 않는다. 캔버스 크기 또는 팀 색이 바뀌면 캐시도 갱신한다. 원본 캐릭터·거점 그림은 그대로다.
- 상태 수신이20Hz여도 움직임 보정에 최소100ms를 사용하던 값을 수신 간격에 맞췄다. 느린 수신에서의 보정과 긴 단절 후 복원은 유지한다. 위치 보정만 바꾸며 전투·HP·명령 권위 상태는 서버가 소유한다.
- 규칙의 `연결·화면 상태`에 도움말을 열기 직전의 FPS, 서버 왕복, 명령→다음 상태 그리기, 수신 간격과 지연을 보여 준다. 복사 내용에 비밀 키·연결 티켓·세션 쿠키는 포함하지 않는다. 메뉴를 연 뒤10FPS로 내려가는 값을 플레이 중 FPS로 오인하지 않도록 열기 전에 측정값을 저장한다.

## 검증

동일 PC의 Chrome 계열 브라우저에서393×665/DPR3/CPU4배 제한, 서버와 분리된 실제 온라인 클라이언트, 지속800기 이동을 사용했다. 별도 로컬 Node 서버가 원래 엔진을 실행했다. 프로파일러를 끈 대조 시험은 각각12초이며 그리는 목표는30FPS로 유지했다.

| 항목 | 기존 | 개선 |
|---|---:|---:|
| rAF 콜백 CPU 평균 | 4.24ms | 2.64ms |
| rAF 콜백 CPU p95 | 11.6ms | 8.4ms |
| 실제 그리기 | 30.01FPS | 30.00FPS |
| 상태 적용 CPU 평균 | 2.48ms | 2.54ms |

그리기와 보간 등이 포함된 rAF 콜백 평균 CPU 비용은 약38% 감소했다. 상태 적용 CPU는 개선됐다고 주장하지 않는다. 기존 대조군도 이 조건에서30FPS였으므로 실제 휴대폰의 FPS가 늘었다는 증거는 아니다. 추가 CPU6배 제한 시험도 수행했지만 PC의 다른 작업 영향을 완전히 통제하지 못하므로 기본 비교는4배 결과를 사용한다.

네트워크 지연을 제외한 결정적20Hz/60Hz 움직임 재생 시험에서, 일정 속도 병력의 표시 위치가 권위 위치보다 늦는 시간은 평균142→74ms, p95150→83ms로 감소했다. 이 값은 전체 터치→화면 지연이나 실제 휴대폰 결과가 아니다. 새 회귀 검사는 빠른 상태 수신에서 추가 표시 지연이 재발하지 않는지 확인한다.

관련24개 검사와 기존 통합133항목, lint(오류0/기존 경고45), Sites 빌드를 통과했다. 단절·늦거나 중복된 상태·느린 수신의 보정도 검사한다. 게임 규칙, 개인200기, 서버20Hz/전투30Hz, 원본 아트와 소리는 바꾸지 않았다.

실제 휴대폰의 GPU 처리시간·발열·통신사별 경로는 이 PC 시험으로 측정하지 않았다. 사용자 기기의 증상이 사라졌다는 결론은 새 버전 재접속 후 해당 기기의 측정값으로 확인해야 한다.
