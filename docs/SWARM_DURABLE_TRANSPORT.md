# 군단 Cloudflare 메모리 전투 서버

영향 범위: 한판 군단의 새 경기만 선택적으로 별도 Worker/Durable Object에 연결한다. 기존 Sites 프로젝트 ID, D1/R2 바인딩, 미로 서버와 다른 게임은 유지한다. 별도 `realtime-swarm/wrangler.jsonc`가 방당 하나의 SQLite-backed Durable Object를 선언한다. Cloudflare 계정 연결과 무료 Worker/DO 공개 배포를 완료했다.

Sites와 전투 Worker에 같은 `SWARM_REALTIME_SECRET`을 비밀 값으로 설정하고, Sites에 `SWARM_REALTIME_URL`을 설정한다. 키와 토큰은 Git에 저장하지 않는다. 운영자가 검증한 서버 설정과 방 allowlist로 새 경기의 전송 방식을 고정한다. 진단용 health 요청 지연으로 조용히 D1 방식으로 돌아가지 않는다. 진행 도중 D1과 메모리 서버를 섞지 않는다. 한판 HttpOnly 쿠키로 현재 참가자를 확인한 후 짧은 연결 티켓을 발급한다. 한 방의 좌석·모드·라운드는 서버가 결정한다.

Sites의 `SWARM_REALTIME_ROOMS`가 빈 값이면 새 방식은 비활성이다. 처음에는 직접 만든 검증방 코드만 쉼표로 지정해, 실제 사용자 경기에 영향을 주지 않고 비교한다. 공개 서버에서 평균과 p95 모두 개선되고 세 모드·재접속이 통과한 뒤에만 `*`로 전체 새 경기에 적용한다. 비워도 이미 선택된 DO 경기는 같은 서버에서 끝까지 진행한다.

전투는30Hz, 상태 전송은 비교 후20Hz(50ms)를 채택했다. 매 프레임 D1 읽기·잠금·저장을 하지 않는다. DO 저장소에 복구용 체크포인트를 보관하며, 명령 상태·번호를 저장한 후 승인한다. 부모 방의 현재 라운드와 참가 상태를 주기적으로 확인해 이전 경기 입력과 퇴장한 좌석을 닫는다. 재접속은 같은 좌석과 명령 번호를 복구한다. 배포 비교가 악화되면 새 경기의 활성화를 끄고 이전 배포로 복구한다.

브라우저는 한판의 `/api/swarm/realtime-connect`에 연결한다. 이 경로가 Origin과 서명 티켓을 확인하고 고정된 전투 Worker로 WebSocket을 중계한다. 외부 주소를 클라이언트 입력으로 받지 않는다. Workers의 WebSocket Response를 보존하면서 vinext가 수정할 수 있는 새 응답 헤더를 만든다. 서버 코드·명령 번호·시뮬레이션은 동일하다. 직접 workers.dev에 연결하던 후보는 아래 비교에서 악화되어 채택하지 않았다.

Workers Free의 SQLite-backed Durable Objects를 우선 사용한다. 유료 플랜 전환은 이 구현의 일부가 아니다. 실제 계정 배포와 공유방 성능 비교 전에는 공개 서비스 개선 완료로 보고하지 않는다.

## 현재 검증과 남은 작업

로컬의 실제 workerd/SQLite DO에서 고정 좌석·공유 강화·중복 비용 방지·서버 재시작 후 상태/명령 번호 복원·퇴장 좌석 차단을 확인했다. 한판 API와 별도 Worker를 연결해1대1/팀전/개인전의 쿠키 인증, 연결 티켓, HTTP와 DO의 이중 진행 차단도 검사했다. 전송 선택과 명령 경로를 포함한23개 검사, 기존 군단 통합131항목이 통과했다. 전체 TypeScript의 기존54개 오류는 남아 있고 신규 군단 경로 오류는 없다.

## 공개 서버 비교 — 2026-11-04

한 PC/회선에서 별도 HttpOnly 쿠키를 가진 참가자들이 실제 한판 공유방에 접속했다. 부모 방 watcher도 실행했다. 각자 동시에 강화 명령을4회 전송하고 다른 참가자의 권위 상태에 보이는 시간을 측정했다. 네 명의 방에서는16개 명령/48개 상대 관측이다. 직접 연결 후보가 악화됐을 때 검증방 활성화를 끄고216으로 실제 복구했다. 이후 수정 후보는 검증방만 다시 허용해 시험했다.

800기는 원래 규칙으로 각자 세 거점을 추가 점령하고 자연 생산해 도달했다. 이 행은 교전 전 밀집 병력에서 강화 명령을 측정한 결과다. 단순 delta 행 개수가 아닌 SnapshotReplica의 전체 생존 유닛 수를 확인했다. 게임 진행은 약1.006배, 명령16개 모두 승인 및 전원 관측, 오류0건이었다. 교전 및 모바일 화면 검사는 별도 수행한다.

해당 PC의 trace 비교에서 한판은ICN(16–21ms), workers.dev는LAX(396–1345ms)로 연결됐다. 게임 연산과 저장이 없는 echo도 직접 연결은650ms/DO경유852ms였다. 같은 게임을 한판 경유로 연결하자 왕복은6ms 내외로 감소했다. 이 결과는 해당 회선의 경로 문제를 보여 주며 전 세계 접속 경로를 보장하지 않는다. 한판 경유는 실제 WebSocket으로 검사했으며 로컬 임시 터널 성능으로 대체하지 않았다.

전송 주기를 두 배로 높여 패킷 빈도도 늘었다. 통신량을 절반으로 줄였다는 뜻은 아니다. 델타 스냅샷·최대3개 미확인 상태의 흐름 제어는 유지한다. 실제 휴대폰의GPU·온도·통신사별 회선·다른 네트워크 참가자 조합은 이 PC 검사로 측정하지 않았다. 승패 규칙, 개인200기 제한, 그래픽과 소리는 변경하지 않았다.

운영 복구: allowlist를 `off`로 바꾸고 검증된 이전 버전을 배포하면 이후 새 경기는 이전 방식으로 시작한다. 이미 시작된 경기는 시작 시 선택한 전송을 유지하므로 운영 중인 경기의 전투 서버나 비밀 키를 갑자기 바꾸지 않는다.216 배포와 해당 소스/아카이브를 보존한다.
