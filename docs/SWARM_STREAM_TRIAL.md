# 연속 상태 전달 실험과 롤백

2026-11-03. 공개 한판의 군단 전투 전송 경로만 실험했다. 규칙, 병력 한도, 그림, 소리, 다른 게임과 방 세션은 변경하지 않았다.

## 가설과 구현

Cloudflare DOOM의 지속 연결과 Colyseus의 서버 상태 전달을 참고했다. 현재 Sites의 문서화된 저장소 선언은 D1/R2이며, 이 프로젝트의 공개 런타임에는 실시간 방용 Durable Object 바인딩이 없다. 따라서 메모리 권위 서버를 연결한 것처럼 가장하지 않고, 기존 D1 권위를 유지한 채 HTTP NDJSON 응답으로 상태를 연속 전달하는 제한된 실험을 했다.

연결은 최대16번 상태를 전달하고 갱신했다. 서버 내부 조회 주기는 목표120ms이며, 입력 트랜잭션과 커밋의 최대32회 DB 왕복으로 작업을 제한했다. 기존 부모 방·경기·쿠키·고정 좌석 확인, D1 잠금과 명령 중복 방지는 유지했다. 브라우저는 조각난 UTF-8/JSON을 조립하고, 스트림 실패 시 기존 단일 폴링으로 복귀하게 했다.

## 공개 서버 결과

각 측정은 독립 쿠키4개로 만든 자체4인 팀전 방에서 진행했다. 각 참가자의 부모 방 변경 감시를 켰고,4라운드에 걸쳐4명이 동시에 강화했다. 각16개 명령의 승인과 나머지3명에게 보이는 시점을 확인했다. 실험방은 대기실 복귀와 퇴장으로 정리했으며 쿠키는 결과에 저장하지 않았다.

| 단계 | 명령 HTTP 평균 | 다른 참가자 상태 반영 평균 | 반영 p95 |
| --- | ---: | ---: | ---: |
| 수정 전 |291.5ms|852.8ms|1186.5ms|
| 연속 전달 실험 |542.6ms|1135.4ms|2097.6ms|
| 원래 버전 복구 후 |289.4ms|866.7ms|1203.2ms|

모든 단계에서16/16명령이 승인되고 모든 상대에게 확인됐다. API 오류는 없었다. 실험에서는 상대 반영 평균이 약33% 나빠졌으므로 공개 버전214로 즉시 복구했다. 실험 커밋 `f695bafe7a332b7e12152260decc1ebd0868e5c2`의 코드는 역방향 커밋으로 제거했고, 과거 Git 이력은 보존했다. 최종 코드는 실험 전 전투 구현과 동일하다.

로컬에서는 스트림·조각난 UTF-8·취소·오류·작업 횟수 제한 검사와 기존 명령/페이싱 검사5개, 실제 API 통합141항목, lint 오류0/기존 경고45, 배포 빌드가 통과했다. 이 통과를 실제 인터넷 성능 개선으로 간주하지 않았으며, 공개 측정 결과를 근거로 롤백했다.

## 해석과 다음 실험의 조건

지속 연결 안에서도 D1 조회·잠금·체크포인트 저장은 계속된다. 기존 클라이언트 왕복에 따른 자연스러운 대기가 없어져 DB 요청 빈도가 늘어난 것이 악화의 가능한 원인이다. 정확한 원인 비중은 DB 시간·대기열·네트워크 시간을 분리하지 않아 확정하지 않았다.

다음 구조 실험은 하나의 방을 하나의 권위 실행 주체에 배정하고, 전투 상태를 메모리에서 계산한 뒤 복구용 체크포인트와 결과를 저장하는 방식이어야 한다. 다수 Worker의 전역 변수만으로 방 상태를 보관하면 일관성과 재접속을 보장하지 못하므로 대체하지 않는다. 실제 연결 가능한 DO 또는 지속 실행 서버와 인증·복구 경로가 필요하다. WebSocket 도입 자체나 업데이트 주기 숫자만으로 지연 개선을 보장하지 않는다.

이번 결과는 한 PC 회선과 소규모 병력의 짧은 공개 시험이다. 실물 휴대폰 GPU·발열·800기 부하 결과나 보편적인 지연 하한으로 해석하지 않는다. 추가 최적화는 실제 서버에서 평균과 p95 모두 비교하고, 기존 세 모드·인증·중복·재접속 동작을 유지해야 채택한다.
