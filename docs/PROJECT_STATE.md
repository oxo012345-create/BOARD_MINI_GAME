# 한판 프로젝트 현재 상태

기준일: 2026-08-18

## 요약

한판은 QR 또는 4자리 방 코드로 접속하는 모바일 파티게임 웹앱이다. 개인전 14개, 모두 협동 7개, 미니(보드)게임 5개 등 현재 게임 선택 화면에 총 26개가 등록되어 있다. 점수표 중심이 아니라 각 라운드의 즉시 결과와 현장 판정을 중심으로 설계되어 있다.

## 공용 시스템

- 방 생성, 4자리 코드, QR 참가, 이름/프로필 선택
- 방장 권한, 방장 이탈 시 위임, 대기실 일괄 이동
- 세션 쿠키 기반 동일 플레이어 복귀와 진행 중 재접속
- 방 상태 저장과 이벤트 갱신
- 게임 시작 전 설명, 종료/나가기 확인
- 사진 촬영 즉시 업로드와 참여자별 사진 목록
- 깜짝 룰 켜기/끄기 및 공용 타이머
- D1 방 상태 저장, R2 사진 저장, Durable Object/WebSocket 기반 미로 실시간 처리
- 모바일 세로 화면과 iPhone 터치/길게 누르기 대응

깜짝 룰 종류는 동물의 왕국, 비밀미션, 모션게임, 금지어, 웃음 참기, 용용체, 이응 게임, TWO TOUCH다. 최초 대기 5분, 진행 10분, 휴식 10분 주기를 사용한다.

## 개인전 게임

| 게임 | 상태 | 주요 기능 |
|---|---|---|
| 오리지널 라이어 | 구현 | 장르/제시어, 라이어만 역할 분리, 누르는 동안 역할 확인 |
| 바보 라이어 | 구현 | 한 명만 다른 단어를 받고 본인이 바보 라이어임을 알 수 없게 처리 |
| 몸으로 라이어 | 구현 | 말 없이 동작으로 제시어 설명 |
| 얼굴로 라이어 | 구현 | 표정으로 제시어 설명, 역할 카드 노출 방식 통일 |
| 라이어-질문 | 구현 | 한 명만 질문을 모르는 변형 라이어 |
| 초성 퀴즈 | 구현 | 술래 오른쪽부터 진행, 방장 정답 공개/다음 문제/결과 |
| 무한 훈민정음 | 구현 | 초성 제시, 막힐 때까지 진행, 다음 문제 지원 |
| 취향 일치 | 구현 | 양자택일 버튼, 선택 완료 상태와 결과별 선택자 공개 |
| 중급 상식 퀴즈 | 구현 | 외부 제공 문제 세트 반영, 정답 공개와 다음 문제 |
| 가짜 추억 찾기 | 구현 | 공통 제시어, 작성 항목 섞기, 가짜 추억 번호/내용 공개 |
| 정확히 10초 | 구현 | 참가자당 한 번, 이름별 측정 결과 공유 |
| 색깔 찾기 | 구현 | 카메라 촬영, 업로드 순서와 이름 표시, 이미지 확대 |
| 초성 물건 찾기 | 구현 | 전체 초성 대상 카메라 촬영/업로드 |
| 아파트 게임 | 구현 | 3명 이상, 인원+2층, 최대 중복→낮은 층 우선 벌칙 판정 |

## 미니(보드)게임

### 장소 마피아

- 상태: 구현
- 인원: 4~8명, 마피아 1명 또는 2명 설정
- 6개 장소 인접 이동, 20초 고정 밤, 살인 담당 마피아의 인접 장소 습격
- 경찰서·광장·병원 특수 규칙, 특수 장소 연속 체류 제한
- 낮 토론, 익명 투표, 동률 시 처형 없이 다음 밤
- 플레이어 이탈 시 일시정지와 재접속 재개
- 낮/밤 픽셀 도시 맵, 역할 길게 누르기, 사망자 화면과 효과음
- 주요 파일: `app/place-mafia.tsx`, `app/place-mafia-shared.ts`, `app/place-mafia-audio.ts`, `app/api/_lib/place-mafia.ts`, `public/place-mafia/`

### 수상한 딜러들

- 상태: 구현
- 인원: 3~8명
- 비공개 소장품 경매, 아이템/조항 카드, 라운드 상태와 결과 판정
- 2D/3D/실사 스타일의 제작 에셋이 보존되어 있으며 현재 화면이 참조하는 에셋과 참고용 에셋이 함께 존재
- 주요 파일: `app/api/_lib/dealer.ts`, `app/page.tsx`, `public/dealer-*`, `tests/dealer-game.test.mjs`

### 미로의 배달부

- 상태: 구현
- 인원: 최대 8명
- 캐릭터 선택, 3D 미로 이동, 서버 판정, 점수와 라운드 진행
- Durable Object/WebSocket 실시간 방 지원
- 주요 파일: `app/api/_lib/maze.ts`, `app/api/_lib/maze-rules.ts`, `worker/maze-room.ts`, `public/maze-courier/`
- 초기 별도 프로토타입은 `archive/maze-map-prototype/`에 보존

### 사라진 보석

- 상태: 구현
- 인원: 4~8명
- 사건 장소·도난품·도구·시간·특징·알리바이·질문·배경 조합
- 특수 역할 선택, 난이도 설정, 개인 사건 파일과 단서 공개
- 모든 단서를 합쳐도 최종 용의자가 2명이 남도록 하는 논리 감사 스크립트
- 50종 알리바이 데이터와 사건/인물/아이템 이미지 에셋
- 주요 파일: `app/api/_lib/gem-heist-data.ts`, `app/api/_lib/rounds.ts`, `app/gem-heist-assets.ts`, `public/gem-heist/`

### CASH AND GUNS

- 상태: 구현, 최근 모바일 UI/BGM 변경의 브라우저 실기기 검증은 미실행
- 인원: 4~8명
- 8라운드, 실탄/공포탄, 캐릭터 직접 조준, 대부 권한, 결단과 총격
- 실시간 예약 드래프트 방식 전리품 분배, 내 자산/보너스 표시
- 혼자 시험할 수 있는 디버그 봇 모드
- 픽셀아트 캐릭터·테이블·전리품·효과음과 반복 BGM
- 주요 파일: `app/cash-n-guns.tsx`, `app/cash-n-guns.css`, `app/api/_lib/cash-n-guns.ts`, `public/cash-n-guns/`

## 알려진 문제와 확인 필요 사항

1. CASH AND GUNS의 마지막 모바일 반응형·전리품·오디오 변경은 사용자의 요청에 따라 저장만 했고, 당시 배포 및 전체 플레이 디버깅을 하지 않았다. 다음 작업 시 가장 먼저 실제 4~8인 흐름과 여러 화면 크기를 검증해야 한다.
2. `public/place-mafia/pixel/`의 미추적 PNG 30개는 제작 과정의 장소/도시 뷰 변형본이다. 백업에는 포함하지만 현재 런타임 사용 여부는 파일별로 다시 확인해야 한다.
3. 과거 대화에서 언급된 독립 게임 **오늘은 내가 요리사**는 현재 `app/page.tsx` 게임 목록과 게임 ID에서 발견되지 않았다. 미로 캐릭터의 “딸기 요리사”와 혼동하지 말고, 필요하면 별도 기능 존재 여부를 다시 조사한다.
4. 프로젝트 루트 밖의 기획서와 미로 프로토타입은 `archive/`로 복사해 보존했지만 운영 빌드에는 포함되지 않는다.
5. 사용자 제공 `public/cash-n-guns/bgm.mp3`의 공개 저장소 배포 권리는 코드에서 확인할 수 없다. GitHub 공개 범위를 정하기 전에 사용 권한을 사용자가 확인해야 한다.
6. 기존 원격은 GitHub가 아니라 Sites 내부 Git 서버다. GitHub 백업용 원격은 기존 `origin`을 덮지 않는 별도 원격으로 추가해야 한다.

## 미완성 또는 후속 작업

- CASH AND GUNS 모바일 실기기/다인 플레이 회귀 테스트
- 모든 보드게임의 4~8인 동시 접속·이탈·재접속 장기 테스트
- 장소 마피아 미사용 후보 이미지 정리 여부 결정. 백업 전에는 삭제하지 않음
- “오늘은 내가 요리사” 독립 게임의 실제 소스 유무 또는 재구현 필요 여부 확인
- GitHub 저장소 생성 후 별도 원격 연결과 백업 push

## 다음 개발자가 먼저 할 일

1. `npm install` 후 `npm run lint`, `npm run build`, `npm test`를 실행한다.
2. `npm run test:gem-logic`, `npm run test:place-mafia`, `npx tsx scripts/cash-n-guns-audit.ts`를 실행한다.
3. 로컬 다중 브라우저로 방 생성→참가→시작→재접속→방장 이탈→결과→대기실 복귀를 확인한다.
4. 변경하려는 게임이 공용 `page.tsx`, `rounds.ts`, DB/Worker 상태에 미치는 영향을 먼저 기록한다.
5. 기존 기능과 에셋을 삭제하지 말고, 사용되지 않는 것으로 보이는 자료도 사용자 확인 전까지 보존한다.
